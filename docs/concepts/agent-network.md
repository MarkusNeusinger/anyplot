This document describes the agent network that lets a visitor paste their own data on a plot page and get that plot adapted, rendered and reviewed ("Use with my data"), and later helps them find the right plot type. It is built with [Google ADK](https://adk.dev) (Python) on Vertex AI (now branded Gemini Enterprise Agent Platform) inside the `anyplot` GCP project: on Claude Haiku 5.5 by default, with Gemini 3.8 Flash as the second arm.

## Goals and fixed decisions

| Topic | Decision |
|---|---|
| Product step 1 | "Use with my data": the user pastes data on a plot page, the network adapts the catalogue implementation for that spec and library to the data, renders it in a sandbox, reviews it with at most one repair round (a render repaired after a rejection is reviewed once more), and returns the image and the code. For measurements only, the eval switch `AGENT_MAX_ATTEMPTS` (`--max-attempts` of the harness) can raise this to three attempts, a second repair round; the default stays one repair round, and a run makes at most two reviewer calls either way |
| Product step 2 | "Find the right plot type", built on the catalogue knowledge that also backs the MCP server |
| Result delivery | Users see and copy both the image and the code: the plot is shown inline in the theme it was rendered in (light unless the user asked for a dark plot), a light and dark switch renders the other theme on demand without any model call, and the image can be copied to the clipboard and downloaded as PNG; the code is shown with syntax highlighting, copied with one click, and downloaded together with `data.csv` so it runs unchanged |
| Plot attribution | Owner decision of 2026-10-10 (variant `s1c-jb-sq2` of the comparison): every PNG the service serves carries a footer strip below the plot, "made with any.plot()" on the left and "anyplot.ai/<spec-id>" on the right, in JetBrains Mono with the dot drawn as a brand-green square. It is composited at image level after the run and never written into the user's code, so the exported `plot.py` reproduces the plot without it. MonoLisa, the site's own font, is not used for it, because its EULA covers desktop, web, application and ePub use only. See [Footer strip](#footer-strip) |
| Render scope | Python first (matplotlib and seaborn in phase 1), designed so the other 13 libraries are additive |
| Data input | Paste text only (CSV, TSV, semicolon CSV, JSON, a Python literal), hard cap 200 KB |
| Access | Visible only in local development and for admins, gated exactly like `/debug/*`; not public in phase 1 |
| Guardrail scope | Allowed: choosing plots, the user's data for them, adapting, rendering and styling, and questions about catalogue code (styling, exports). Everything else gets a fixed refusal |
| Runtime | Two Cloud Run services of their own: `anyplot-agents` runs the agents, and `anyplot-renderer` runs the code in Cloud Run sandboxes (owner decision of 2026-10-10, so a local `adk web` and the deployed agents service share one renderer). | Model | Owner decision of 2026-10-09: Claude Haiku 5.5 (`claude-haiku-5-5`) on Vertex AI, location `eu`, is the phase-1 default for every agent and for the scope and dataset judge (`AGENT_PROVIDER=anthropic-vertex`). Gemini 3.8 Flash (`gemini-3.8-flash`, with the judge on `gemini-3.5-flash-lite`) stays the second arm behind `AGENT_PROVIDER=gemini`, so the two can be compared on price and quality. The judge follows the provider: `AGENT_JUDGE_MODEL` must be a model of the same family. Every model id is an exact pin, never an alias such as `gemini-flash-latest`: that alias is undocumented on Vertex, its served version is unobservable, and it returned 404 once when its target retired. "3.8" in this document always means the Gemini model, never a Python version |
| Python | Python 3.13 everywhere, the same as the pipeline |
| Location | The `eu` multi-region from day one. No Gemini 3.x Flash is served in europe-west4; `eu` keeps ML processing in the EU at +10 % price and is compatible with the privacy page's EU claim |
| Language | Owner decision of 2026-10-12: one session language for the replies and every text in the plot (title, axis titles, legend entries, annotations), English by default like the whole site, also when the browser is set to another language. The first typed message sets it to the language it is written in, and a choice from the chat header's chip or a request in the chat sets it for good (see [Session language](#session-language)). Code, code comments, the `changes` notes and the root's `change_request` to the adapter stay English; column names, units and category labels from the data keep the user's spelling in every language |
| Quick feedback | From phase 1, one click plus a short text on any result submits the whole case (conversation, code, images, data profile, optionally the data file, model and prompt config) for tuning; opt-in for real users later |
| Model-version testing | From phase 1, a regression harness so a newer model version, the other provider's arm, or a prompt change is one command or one workflow dispatch with a diff report against the pinned baseline |
| Catalogue normalisation | A parallel pipeline workstream makes catalogue code data-derived and canvas-correct at the source |

## What the research settled

- **ADK 2.11.0, 2.x idioms only.** `from google.adk import Agent, Workflow, Event, Context`; plugins on `App(plugins=[...])`; sub-agent modes `task` and `single_turn`; a `Workflow` with a Pydantic `input_schema` passed in `tools=[...]` becomes a NodeTool whose progress events reach the stream. `SequentialAgent`, `LoopAgent` and `ParallelAgent` are deprecated, `AgentTool` is discouraged (its events never reach the stream), `global_instruction` is deprecated, and `GOOGLE_GENAI_USE_ENTERPRISE=TRUE` replaces the Vertex flag. `abort_signal` is a `Runner.run_async` keyword argument, not a `RunConfig` field. `instruction` strings get `{var}` state templating (a missing key raises); `static_instruction` is sent unchanged.
- **ADK's own server is never exposed.** `adk web`, `adk api_server` and `get_fast_api_app` are unauthenticated and let the client choose the user id and write state, events and artifacts. The network embeds `Runner.run_async` in its own FastAPI routes.
- **No agent gets a `code_executor`.** ADK auto-runs the first fenced code block the model emits. Rendering is a deterministic tool that calls Cloud Run sandboxes (`gcloud beta run deploy --sandbox-launcher`, gen2, Preview, no extra cost): `sandbox do` has no egress, no environment, secrets or metadata server, and a read-only root filesystem. Region availability and Chromium, R and Julia inside the sandbox are undocumented, so a spike gates phase 1.
- **Adapting catalogue code is not a data swap.** 172 of 325 matplotlib files set axis limits with data-scale literals, 87 place annotations at numeric data coordinates, literal statistics are common, and 137 matplotlib and 138 seaborn files already fail the 3200x1800 canvas gate (`bbox_inches='tight'`). A pure swap passes the structural gates in 40 of 63 runs and 0 of 7 for date axes. Structured search-and-replace hunks of about 100 to 180 output tokens passed all gates in a proxy test. Inline data literals are infeasible beyond a few hundred rows, so data travels as a sidecar `data.csv`.
- **Catalogue access is in-process.** The six FastMCP tools in `api/mcp/server.py` are plain async functions, but they raise `ValueError` (which aborts an ADK run unless handled), and over HTTP every result reaches the model twice. Their category-scoped AND search, `# noqa` stripping and slimmer payloads (no review internals) landed on 2026-10-09, so the in-process wrappers only need error handling and fencing.
- **Infra constraints.** `anyplot-api` is a single Cloud Run instance (1 vCPU, 1 GiB, concurrency 40) running as the default compute service account with `roles/editor`; `anyplot-images` is a public bucket; `aiplatform.googleapis.com` is not enabled; the API image has no plotting extras, R, Julia, Node or Chromium.
- **Privacy.** The privacy policy in `app/src/pages/LegalPage.tsx` says the AI never sees a visitor's request and that everything runs in europe-west4. The owner-only phase 1 is compatible. Any non-owner use needs a legal-page PR, a retention design, and the owner's answer on the GCP agreement type (abuse-monitoring prompt logging for up to 90 days under the standard terms).
- **Cost on `eu` with Gemini 3.8 Flash (now the second arm).** List price $1.65 input and $8.25 output per 1M tokens; a 50 % credit makes the effective price $0.825 and $4.125 through 2026-12-31. The judge model costs $0.33 and $2.75. Spike X measured a median of $0.124 per passed plot at list price on 2026-10-10 ($0.062 at the promo price), above the $0.05 line at either price, against $0.0041 for Claude Haiku 5.5; a model of the adapter truncation fix from that run keeps the Gemini median near $0.125. Spend caps count list price, not the promo. Gemini 3.8 Flash is in the short-term availability tier (no retirement date yet, at least 45 days' notice) and not on the Standard PayGo tier list, so expect 429s and plan a model bump gated by evals.

## Architecture

```
Browser ──fetchWithAuth──► anyplot-api  /debug/agent/*   (require_admin → AdminIdentity, CSRF header, AGENT_ENABLED kill switch)
                             │ ID token (roles/run.invoker) + X-Anyplot-User + X-Request-Id
                             ▼
                       anyplot-agents  (Cloud Run gen2, --no-allow-unauthenticated, own service account)
                         FastAPI /v1/* → run queue (1 in flight, 1 start a minute, 600 s maximum wait)
                           → Runner(app=App(plugins=[ScopeGuard, Budget, ToolSafety, ContextFilter(6)]))
                           root "anyplot" ── session tools ── plot_pipeline (Workflow NodeTool, input_schema=PipelineArgs)
                                @node run_pipeline:  adapter → apply + validate → render, one theme → gates
                                                     → reviewer (≤1) → repair (≤1) → Event(output=PlotResult)
                         POST /v1/.../versions/{v}/render → render the other theme → gates   (no model call, no queue)
                             │ every render: `remote` backend, ID token (roles/run.invoker)        adk web on a developer machine
                             ▼                                                                       │ the same `remote` backend
                       anyplot-renderer  (Cloud Run gen2, --sandbox-launcher, --no-allow-unauthenticated, zero-role account)  ◄┘
                         FastAPI POST /render → one render slot → per theme: sandbox do (gVisor, no egress) → raw outputs
```

Only one agent talks to the user. Everything the research shows an LLM does not improve (parsing, default bindings, the data loader, the canvas, safety checks, export) is plain code.

The root's "never" list, enforced by the stream translator and the evals: never write or run code (code changes happen only through `plot_pipeline`; code answers are short prose that references lines from `get_current_code`; the translator strips fenced code blocks longer than 10 lines); never invent spec ids; never paste data rows (naming a single value the user asks about is fine); never emit links (a scheme or `www.`; a bare web address such as `jana-novak.de` is data), HTML or markdown images; never claim success unless `PlotResult.status` is `ok` or `needs_attention`.

Rules for every agent:

- Models come only from `make_model()` in `agents/anyplot/models.py`, which builds the model of the configured provider. On `anthropic-vertex` (the default) it returns `VertexClaude`, ADK's `Claude` with an `AsyncAnthropicVertex` client built from the settings, adaptive thinking on the root and the adapter (`AGENT_ROOT_THINKING_BUDGET`, 1,024, and `AGENT_ADAPTER_THINKING_BUDGET`, 2,048, each at most 4,096 and added to that agent's output cap; 0 turns it off, the reviewer never thinks, and the eval harness overrides both with `--thinking-budget`; a replayed thinking block whose signature no longer matches the conversation, which happens when ADK moves the session block between the root's calls, is dropped by the API through the `thinking-binding-controls-2026-08-01` beta instead of failing the call with a 400), and Claude's structured outputs for the adapter's and the reviewer's response schemas, because ADK 2.11 sends no response schema to Claude: the request's `output_config.format` carries the schema made strict by the SDK's `transform_schema`, so constrained decoding enforces types, enums and required fields, and the Pydantic schema with its repairs checks the lengths and counts the grammar cannot. On `gemini` it returns `Gemini(model=..., client_kwargs={"enterprise": True, "project": ..., "location": settings.location}, retry_options=HttpRetryOptions(attempts=3, initial_delay=1))`. The bare `Gemini()` default is the retiring 2.5 Flash and is never used.
- No `FallbackModel` in phase 1. A fallback would need a second model id or the `global` endpoint, which breaks the pins; persistent 429s map to `error{code:"capacity"}`. A named fallback on `eu` is an explicit owner decision; switching `AGENT_PROVIDER` is a configuration change, not a fallback.
- Low-cardinality `labels` in every agent's generation config. On Gemini: explicit `safety_settings` at BLOCK_MEDIUM_AND_ABOVE, and no temperature, top_p or thinking budget on Gemini 3.
- `agents/anyplot/agent.py` keeps an explicit registry `ALL_AGENTS = [root_agent, *ADAPTERS.values(), reviewer]`, because the adapters and the reviewer are started with `ctx.run_node` and a tree walk from the root would miss them. A unit test iterates the registry and `App.plugins` and asserts: no `code_executor`, `google_search`, `url_context`, `AgentTool`, `LoggingPlugin` or chat-mode sub-agents; no agent has a non-empty string `instruction`; every model string and client location comes from settings.
- Settings defaults in `AgentSettings` (`agents/anyplot/settings.py`, read from `AGENT_*` variables): `provider="anthropic-vertex"`, `model="claude-haiku-5-5"`, `judge_model="claude-haiku-5-5"`, `location="eu"`, `root_thinking_budget=1024`, `adapter_thinking_budget=2048` (the 2026-10-11 measurement: with both, every one of the 122 cases passed the gates and 51.6 % ended `ok`, against 91.0 % and 28.7 % with thinking off, for a median of $0.0063 instead of $0.0038 per plot and a p50 of 31.5 s instead of 13.6 s; Gemini ignores the budgets and refuses a non-zero budget set explicitly, while an explicit 0 is accepted). The Gemini arm sets `AGENT_PROVIDER=gemini`, `AGENT_MODEL=gemini-3.8-flash` and `AGENT_JUDGE_MODEL=gemini-3.5-flash-lite`. The settings refuse `-latest` aliases, model ids that do not match the provider, Claude models outside `CLAUDE_MODELS` (newer Claude models refuse disabled thinking with a 400), any location other than `eu`, `us` or `global`, and `renderer="local"` outside development.

Deviations from the first sketch, each evidence-backed: there is no data-intake LLM agent in step 1 (about 320 of 325 specs declare typed `## Data` role bullets, so default bindings are deterministic and confirmed in UI dropdowns; parsing must be code anyway because `thousands='.'` silently corrupts `DD.MM.YYYY` dates); the reviewer is tool-less (GA image path, native `response_schema`, nothing persisted in session events, no `load_artifacts` listing of `data.csv`); the domain knowledge lives in tools and prompts rather than in a separate expert agent.

### Request flow for "Use with my data"

1. The `.adapt()` overlay button in `SpecDetailView` does a full navigation to `/debug/agent?spec=&library=&language=`.
2. `POST /debug/agent/sessions {spec_id, library, locale}`. The BFF validates the spec and library against `core/constants.py` and the enabled libraries from anyplot-agents `GET /v1/status` (cached), loads a catalogue snapshot through `core/catalogue/queries.py` (title, description, data roles, notes, noqa-stripped code, library version), derives the user id, and forwards it. anyplot-agents normalises the code, runs the readiness scan and the SECURITY validator, and answers `422 not_eligible` for blocked pairs (the 13 map specs, validator failures, files without a `THEME` block or with a non-literal savefig target). anyplot-agents has no database access in phase 1. `GET /debug/agent/eligibility?spec=&library=` gives the button the same answer. `locale` is the browser's locale, recorded with a feedback case; it sets no language, and every session starts in English (see [Session language](#session-language)).
3. `POST .../dataset {text}` runs the deterministic parse and returns a 20-row preview, the `DatasetProfile`, default bindings and warnings. A deterministic pre-filter over every header and cell for text addressed to an AI, then the dataset judge with a data rubric, refuse instruction-like datasets. Both look for injection only: names, postal and e-mail addresses, phone numbers, web addresses and amounts are the user's data and plot like any other value. The judge sees every header and the same five sample rows and five top values the root and the adapter get, with cells in full, in parts of about 4,000 characters, one judge call per part (one part for every eval fixture). No other LLM call happens for a table. Text that is no table the parser can read (prose such as "a bar chart with dog 7, cat 3 and bird 4", a list typed one value per line; at most 4,000 characters, never a JSON array or object, which the parser reads or refuses itself) takes the transcriber path instead (owner rule of 2026-10-11): the pre-filter runs on the raw text, the judge model reads it under the `TranscribedTable` schema (`agents/anyplot/data/transcribe.py`, rubric `prompts/transcriber.md`: keep every value as written, invent and compute nothing, a note on anything ambiguous), the table's CSV is parsed like a paste, and the route answers `transcribed: true` with that CSV, the preview and the note, storing nothing. The page shows the table for the user to confirm or discard, because a wrong reading makes everything after it wrong; confirming posts the CSV through this same route with `confirmed: true`, which skips only the free-text fallback (a one-column table would otherwise be read again), while the deterministic parse, the pre-filter, the judge and the store run as for any paste.
4. The user adjusts the bindings in dropdowns (`PUT .../bindings`), confirms the data with its bindings (`POST .../dataset/confirm`, step 1 of two, see "Two steps: data first, then the plot" below) and clicks **Create plot**, which sends `POST .../messages {action: "create_plot"}`. The server sets the context variable `REQUEST_KIND=action`, so the judge is skipped, and sends a fixed message. Every turn first enters the run queue (see the bounds table below): the stream sends `ready`, then `status{step:"queued", position, waiting}` while the run waits, and the request deadline starts only when the run leaves the queue.
5. Root call 1 calls `plot_pipeline({})`. `PipelineArgs` has no spec, library or dataset field; those come from server-set session state, so neither the model nor an injection can redirect the pipeline. Its `theme` (`light` by default) is the one theme the run renders and the reviewer sees; the root sets `dark` only when the user asks for a dark plot, and keeps the latest version's theme, which its session block names, for a change. Without a dataset, with incomplete bindings or without the user's confirmation of the data the pipeline returns `PlotResult(status="not_ready", reason=...)` (`no_dataset`, `incomplete_bindings`, `data_unconfirmed`) before any LLM call.
6. The pipeline streams `adapting`, `checking`, `rendering`, `reviewing` and `repairing` and always ends with `Event(output=PlotResult)`. A `None` output would raise `NodeInterruptedError`.
7. Root call 2 writes a short reply in the session language. The UI fetches the PNG of the rendered theme (with the footer strip), `plot.py` and `data.csv` through the BFF. The light and dark switch calls `POST .../versions/{version}/render {theme}`, which renders the other theme from the version's stored run form (the same code and data) through the render backend and the host gates, with no adapter, no reviewer and no queue, and answers synchronously.
8. Free-text follow-ups go judge → root → `plot_pipeline(change_request, base="previous")`, `set_bindings`, `set_language` (a request such as "labels in English"), or a code answer through `get_current_code`. The session's first in-scope typed message also sets the session language when the user has not chosen one. The library pills call `POST sessions/{sid}/library`, which loads a new snapshot and keeps the dataset and bindings.

The pipeline is a code-bounded loop, never a graph cycle, wrapped as `plot_pipeline = Workflow(name="plot_pipeline", input_schema=PipelineArgs, edges=[("START", run_pipeline)])` so the tool name is stable:

```python
@node(rerun_on_resume=True)
async def run_pipeline(ctx: Context, node_input: PipelineArgs):
    s = PipelineState.load(ctx)                        # spec, library, snapshot, dataset_id, bindings (server-set)
    if not s.ready:
        yield Event(output=PlotResult.not_ready(s.reason)); return
    deadline = SoftDeadline(140)                       # abort_signal at 180 s is the hard backstop
    best, best_defects, best_reviewed = None, [], False  # the best render that passed R1+R2 and whether the reviewer saw it
    review_defects, reviews, feedback, reason = [], 0, [], None
    try:
        for attempt in range(1, settings.max_attempts + 1):   # AGENT_MAX_ATTEMPTS, 2 by default
            if not budget.check(ctx): reason = "budget"; break
            if attempt > 1 and not deadline.allows(adapter_p95 + render_p95): reason = "deadline"; break   # 60 + 15 s
            yield Event(message="adapting" if attempt == 1 else "repairing")
            req = s.adapt_request(node_input, feedback, allow_full=(attempt >= 2))   # code = latest validated working form
            plan = await ctx.run_node(adapter_for(s.library), req)
            yield Event(message="checking")
            working, feedback = apply_and_validate(s, plan)   # edits → ADAPTED-profile validator (placeholder allowed)
            if feedback: continue
            yield Event(message="rendering")
            run_form = substitute_loader(normalise(working))  # the run form is the exported code
            job = s.render_job(run_form, themes=(node_input.theme,))   # one theme per run
            result = await renderer.render(job, timeout=deadline.clamp(render_timeout))
            if result.passed_host_gates:                     # R1 and R2 passed; R3 passed or was padded
                best, best_defects, best_reviewed = result, result.defects, False
            feedback = result.defects                        # R3 miss and advisory probe gates feed the next attempt while one is allowed
            if feedback and attempt < settings.max_attempts: continue
            if reviews == 2: break                           # both reviews used: nothing left to repair for
            yield Event(message="reviewing")
            verdict = await ctx.run_node(reviewer, s.review_request(run_form, result))
            reviews, best_reviewed = reviews + 1, True
            review_defects = [d.as_line() for d in verdict.defects]
            feedback = review_defects
            if verdict.ok: break
    except Exception:
        reason = "error"
    finally:
        yield Event(output=s.finish(ctx, best, best_defects, best_reviewed, review_defects, reason))  # every path
```

`finish` returns `ok` only when `best` exists, the reviewer saw exactly that render (`best_reviewed`) and passed it, and the canvas was not padded; `needs_attention` when `best` exists but either the last review rejected it (its lines become residual defects), or the reviewer never saw it after giving defects (a repair whose second review the budget or the deadline skipped, or whose answer could not be read; the first review's lines become residual defects), or the canvas had to be padded, or advisory probe gates still report defects; `failed` when no render passed R1 and R2, with `reason` in `validation`, `render`, `deadline`, `budget` or `error`. The translator maps an abort without a `PlotResult` to `error{code:"deadline"}`.

#### Bounds

The owner decided the queue, the rate and the serial renders on 2026-10-09, after spikes S and S2 showed that one instance with 4 GiB serves one sandbox at a time safely.

| Renders per run | one round per attempt, of one theme (`PipelineArgs.theme`, `light` by default) | the pipeline loop |

The stress cases (`agents/evals/fixtures/cases/stress-*`) each name the bound that must stop them; `python -m agents.evals.matrix --cases stress --static` checks the model-free ones without a model, and the [fixtures README](../../agents/evals/fixtures/README.md#stress-cases-what-bounds-them) records what each measured.

A typical "Create plot" costs 4 LLM calls (root twice, adapter, reviewer); a repair adds one, and the review of a render repaired after a rejection one more; each free-text turn adds one judge call; the theme toggle costs none.

The run queue (`agents/anyplot/run_queue.py`) is an in-process FIFO in front of whole `/messages` turns, the memory, rate and cost limiter of the instance. It has two lanes: a `premium` entry goes before every `normal` one (first come, first served within a lane), but the concurrency and rate limits bind it too. Nothing sets `premium` yet; it is the lane for users who later pay for their own tokens. While a run waits, the stream sends `status{step:"queued", position, waiting}` at once, on every change, and every 15 s unchanged, so idle proxies keep the stream open; `position` 1 runs next and `waiting` counts every queued entry, this one included. A client that disconnects while it waits leaves the queue, and `POST .../cancel` takes a waiting run out at once. The run registry, which answers `409 run_active`, covers queued runs and theme toggles as well as running turns, and its stale sweep frees an entry whose stream vanished after the maximum wait or the deadline, plus a margin of 30 s. A queued turn counts as use of the session's dataset, so the idle sweep does not take it while the run waits. `GET /v1/status` reports `waiting` and `in_flight`. Runs that `adk web` starts bypass the queue, because they never pass through `/v1`; their renders still go through the one render slot.

The queue length is the owner's formula and assumes that a run ends within the 60 s rate window. A run that takes longer holds the only slot past the window, so every later start slips by the difference: with one run in flight, ten accepted entries and 90 s runs, the last four wait the full maximum and end with `capacity`. Admitting by an estimated start time (the position times the larger of 60 s per start and the recent run time) would keep that promise; it is an open decision.

### Two steps: data first, then the plot

Owner decision of 2026-10-11: "Use with my data" is an explicit two-step flow. Step 1 is the data, and it ends with the user's confirmation that the table and its bindings fit the plot. Step 2 is the plot, as described above. The owner's principle: in any real analysis the data must be right first, or everything after it is wrong.

Principles:

1. Step 1 is a stop only when it has to be. A clean paste (the parser happy, the bindings complete, no ambiguity warning) shows the preview and the bindings with `.confirm()`, one click from the plot. Nobody with a clean CSV has to talk to an agent.
2. The model never writes data rows. It will choose operations from a fixed set, the server applies them with pandas to the stored canonical CSV, re-parses the result and stores it as the next dataset version with a change list and `.undo()`. The transcriber for free text is the one exception, and its table is confirmed by the user before it is stored.
3. One truth on the screen: the preview table is always the current version. Every model step shows what changed and needs the user's confirmation. Step 2 stays locked until the data is confirmed, on the server: the pipeline answers `not_ready` with `data_unconfirmed` (`load_inputs` in `agents/anyplot/pipeline.py`), so neither the model nor a stale page can start a plot on data the user has not looked at.
4. The most common real preparation is aggregation (single bookings into sums per month or category), so it belongs to the first set of operations.

Built since 2026-10-11 (the gate): `POST /v1/sessions/{sid}/dataset/confirm` stores a fingerprint of the dataset id and the bindings as the user saw them (`anyplot.confirmed`, `confirmation_fingerprint`); the pipeline runs only while the fingerprint of the current state equals it. A new dataset gets a new id, so a paste or a transcription's `.use()` drops the confirmation by itself, and so does any binding change through the `PUT` route or the root's `set_bindings` tool, also one that lands between the confirmation's read and its write, because the stored fingerprint then names bindings the session no longer holds; a library switch keeps the data, the bindings and the confirmation. The session block tells the root whether the data is confirmed, and the root answers `data_unconfirmed` by asking the user to confirm in the data panel, which it cannot do itself. The page shows a step header `1 data · 2 plot`, `.confirm()` after the bindings, and `.create_plot()`, which starts a run only after the confirmation (before it, the button explains the step instead of calling the server); the eval harness and the development fixture confirm on the user's behalf, because their data is the developer's own.

Built since 2026-10-11 (the operations): the root tool `prepare_data(operations)` with at most five operations per call, each a Pydantic model of the fixed set in `agents/anyplot/data/prepare.py`: `rename` (column, name), `drop_columns` (1 to 10 columns), `drop_rows` (`where` conditions on one column each, all of which must hold: `eq`, `ne`, `contains`, `is_missing`, `gt`, `lt`, at most three; a value is compared, never evaluated), `set_type` (number, datetime or text, with the date format and the decimal separator; to number is for the columns the profile still shows as text, because a column whose every cell carries the same unit is already numbers after the paste, the unit in its name such as `Anteil (%)`: one unit such as `%` or `EUR` is removed and the cells are read as the parser reads a number, the other mark a thousands separator between three-digit groups only, and when more cells read with the other decimal mark the whole column is read that way and the change line says so; a cell that cannot be read becomes missing, more than 10 % of them is a `type_mismatch`; to text the column stays text through the re-parse of every later version, stored with the version as `text_columns`; `MM/DD/YYYY` on a column that is already dates swaps day and month only for a slash column the parser flagged as ambiguous), `aggregate` (by one or two columns, a value column, `sum`, `mean`, `count`, `min` or `max`, and a `month`, `quarter` or `year` period for a datetime key), `sort`, `pivot_longer` (2 to 20 columns into a name/value pair; a long format over the parser's 200 KB cap is an `invalid_operation`) and `pivot_wider` (the distinct values of a column become at most 50 columns; duplicate pairs are refused, never aggregated silently), and, since 2026-10-12, `classify` (a new text column whose cells are labels: each row gets the label of the first of 1 to 10 rules whose `drop_rows`-style conditions all hold, else `otherwise` or a missing cell; labels are at most 40 characters, never a token the parser reads as a missing cell such as `NA` or `-`, exempt from ToolSafety's link rule like a rename's name, and the column stays text through every re-parse). `classify` came from the owner's case of 2026-10-12: a generated sine table on `bar-feature-importance` had no text column for the `feature` role, and "positive is class 1, negative class 2" had no operation, so the root had to refuse. No expression language (an injection surface), no joins, no model-guessed fills: the operations only move, type, aggregate, drop or label cells that are there, and `ToolSafety` validates the list against the same models before the tool runs. The server applies them with pandas to the stored canonical CSV, re-parses the result with `parse_dataset` (the dataset judge does not run again: the only new text is a rename's name or a `classify` label, which the model writes from a user message the scope judge already checked) and stores it as the next dataset version (`agents/anyplot/dataset_versions.py`): the previous version joins `anyplot.dataset_history`, which keeps the last five (older ones leave the store; the idle sweep takes a session's history only together with its current version), `anyplot.dataset_version` counts up from the paste's 1, the bindings are carried over (`carry_bindings`: the ones still valid stay, the roles left without one get the defaults), and the confirmation drops by itself because its fingerprint names the dataset id. The tool answers the change lines (one English line per operation with its counts, fenced as `<tool_notes>`) and the new profile (fenced as `<user_data>`), or a `PrepareError` code (`unknown_column`, `type_mismatch`, `empty_result`, `too_wide`, `invalid_operation`) with a message that names columns at most. The page learns about a changed dataset from the `done` event: after a turn that changed the dataset id it carries `dataset: {preview, profile, bindings, warnings, roles, changes, version}`, the dataset route's shape plus the turn's change lines (`roles` since the formulas below), and `data_confirmed: false`; the BFF relays a `done` of up to 512 KiB whole (every other event stops at 64 KiB), which the largest dataset the parser accepts fits (`agents/stream.py`, `MAX_DONE_EVENT_CHARS`). `POST /v1/sessions/{sid}/dataset/undo` (the user's `.undo()` button; the model has no undo) restores the newest history entry as the current dataset, bindings carried over, unconfirmed again, and answers like the dataset route (`422 nothing_to_undo` for a paste that was never changed). The step-1 summary is the action `{"action": "summarize_data"}` on the messages route (judge skipped, like `create_plot`): the root reads the profile, which now carries `mean` and `median` for numeric columns, and answers in two to four sentences (rows, columns with types and units, missing values, values that look like percentages, the proposed bindings, one question when something is ambiguous), never claiming the data is right: the user confirms. The live eval `agents/evals/prep.py` scores the root's choices on `agents/evals/fixtures/prep/` by exact operation match, order-insensitive, with an 80 % gate (see [Run the prep eval](../../agents/README.md#run-the-prep-eval)). The page asks for the summary right after every parse that stores a dataset (a paste, or a transcription's `.use()`; never after an undo or a library switch), so it is the first turn in the thread, and the composer takes data requests in step 1. A `done` with `dataset` replaces the preview, the profile and the bindings, takes the page back to step 1, and shows a `# changed` block above the preview with the change lines and `.undo()`; after an undo the block names the restored version and keeps `.undo()` while the version is above 1, until the service answers `nothing_to_undo`.

Built since 2026-10-11 (formulas): owner decision of 2026-10-11, a function such as "sin x von -pi bis pi" is a deterministic data source in step 1, not a path around the data layer. The root tool `generate_data(variables, series)` takes a spec, never rows: one or two variables, each a range `{name, start, stop, points}` (`start` and `stop` are expressions over numbers and the constants `pi`, `e` and `tau`; 200 points by default, at most 5,000; two variables make a grid of every pair, the first variable slowest, at most 10,000 rows), and one to ten series `{name, expression}`. The server computes the table with NumPy (`agents/anyplot/data/generate.py`). The expressions are a whitelist over Python's `ast`, evaluated by walking the checked tree and never passed to `eval`: numbers, the variables, the three constants, unary `+` and `-`, `+ - * / ** % //`, parentheses, and the functions `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `sinh`, `cosh`, `tanh`, `exp`, `log`, `log10`, `log2`, `sqrt`, `abs`, `floor`, `ceil`, `round` and `sign` with one argument and `atan2`, `min` and `max` with two, at most 200 characters and 100 nodes per expression. Anything else (attributes, indexing, strings, comparisons, conditionals, lambdas, comprehensions, keyword arguments, `^`, `2x`, a `#` comment) is `invalid_expression` with a message that names the construct, such as "'^' is not a power; write x**2"; the typographic operators `−`, `×` and `·` read as `-` and `*`, so the change line quotes nothing but the checked expression. Every value is a float64 array under `np.errstate(all="ignore")`, so an overflow, a division by zero or a logarithm of a negative number becomes a missing cell, never an exception; a change line counts such cells per series (`y: 12 of 200 values are undefined and left empty`), and a series with no defined value is `undefined`. The other codes are `invalid_range` (an endpoint that is not finite, equal endpoints, or a range so narrow for its points that two of them round to the same value), `too_many_points` (a grid over 10,000 rows) and `too_large` (a table over the parser's 200 KB input cap, which three columns of eight-digit numbers reach at about 6,000 rows; the message names about how many rows fit, and for a grid how many points each). Every value is rounded to eight significant digits and written as the parser writes a number, the variables before the series are computed, so every row holds `y = f(x)` for the `x` it shows; the table re-parses as number columns and becomes an ordinary dataset version: the next version through `push_version` when the session has data (undo restores the previous one), or version 1 the way the dataset route stores a paste when it has none; either way the confirmation drops by itself and the bindings are the defaults for the new columns, never the ones made for the old data, even where a column name such as `x` returns (`push_version(rebind=True)`). The tool answers like `prepare_data` (the change line, such as `generated 200 rows: x from -3.1416 to 3.1416, y = sin(x)`, fenced as `<tool_notes>`, and the new profile fenced as `<user_data>`), and `ToolSafety` validates the spec against the same model first, with the link rule over every string. The plot and its export (`plot.py` with `data.csv`) use the generated table like any other. Since a first dataset can now come from a chat turn, `done.dataset` carries the spec's `roles` too, at most 50, like the dataset route. The dataset route refuses pasted text that looks like a formula with `422 formula` before the transcriber would read it, because a model would compute the rows (`looks_like_formula`); only text within the chat's 2,000-character cap is refused this way, because the page's offer sends the refused text to the chat as a turn, and longer text reaches the transcriber, whose rubric computes nothing. The guard reads no delimited table, and reads the rest line by line and sentence by sentence, each of at most 300 characters: a formula is a call whose argument uses a variable (`sin(x)`, `sin x`, `√x`; never `Max(3)`, a name with a count), an assignment of an expression to a short name (`y = x**2`, `f(x) = 2x + 1`; never `Äpfel = 3x`), or a range phrase with numbers or `pi` next to a constant, a one-letter variable before it (`für n von 0 bis 10`), a power or a curve's name such as "Parabel" or "Sinuskurve". A unit is no sign of a formula (`m²`, `CO2 in t`), and neither is a word that data has as well, such as "curve", "Funktion", "exp" or "Quadratmeter". Text that holds its own values is data, whatever else it says: three numbers or more outside the formula's ranges, expressions, parameters and point counts (`Umsatz von 2020 bis 2024: 10 12 15`) send it to the transcriber. A formula request in one sentence of more than 300 characters is not caught; the transcriber's rubric covers it (compute nothing, write only the values the text holds). The scope judge treats a request to draw a function, curve or distribution shape as in scope, never `needs_data`, and four formula cases joined the prep eval.

### Session language

Built since 2026-10-12 (session language): owner decision of 2026-10-12, a session has one language for the replies and for every text in the plot, and it is server-set state (`anyplot.language`, `anyplot.language_source`), never a rule the root re-derives each turn. It starts as `en` with the source `default`, whatever the browser's locale, so a message such as "sin x" gets an English plot. A language is a short name or code that matches `^[A-Za-z][A-Za-z -]{0,39}$` (`agents/anyplot/language.py`); a known English name or endonym is stored as its code (`Deutsch` and `German` as `de`), anything else as typed (`Swedish`).

The session's first in-scope typed message sets it to the language the scope judge names for that message (`lang`, which the judge returns for every free-text turn), with the source `detected`. An `en` verdict counts only for a message of at least three words, because the judge also answers `en` for a message without a clear language: `sin x` keeps the default, and the next typed message is judged again. A later typed message never changes a recorded value; a refused message and the actions `create_plot` and `summarize_data`, which skip the judge, never set it; and the keys outlive a library switch. The chip in the chat header (`lang: en`, `lang: de · detected`, `lang: de · chosen`) lists the ten common languages, the site's ten most used visitor languages in Plausible in that order (`en`, `zh`, `de`, `vi`, `es`, `fr`, `nl`, `pt`, `ru`, `it`), and a free-text field for any other. A choice calls `PUT /v1/sessions/{sid}/language` and sets the source `chosen`, which detection never overrides. A request in the chat ("labels in English", "Beschriftung auf Deutsch") makes the same change through the root's `set_language(language)` tool, which the server validates like `set_bindings` and refuses while a plot run is active. Its result carries no value: it says whether the session language `changed` (`de` against `Deutsch` is no change), for the reply, and whether the plot is `plot_outdated`, that is, whether the library's latest rendered version has its text in another language. Only `plot_outdated` makes the root write the next version in the new language, because the two can differ: a plot made by the `create_plot` action before any typed message stays English after a later German message records `de`. A German user who asks for English labels therefore gets English replies from then on: there is one session language.

Every prompt that carries the value fences it as `<plot_language>`, data, never an instruction, because a chosen language is free text; the value is still the language to write in. The session block names how it was set on a fixed line (`LANGUAGE_SOURCE_LINES`: "chosen by the user (in the chat header, or asked of you)") under a heading that says to write the replies and the plot text in it. ADK sends this dynamic block inside the user's turn, between its instruction markers, so the root prompt says the server wrote it, to follow it and never to call it a block in the user's message; a production session of 2026-10-12 (`20261012T211551Z-bcc5bcf1`, "klingon" in the chip) had the root refuse it as an injection and stay in English, and on 2026-10-13 the page's English `[action]` messages still set the reply language until the prompt said they do not. A language the model cannot write gives English with one sentence that says so, and the adapter notes it in `changes`. The adapter's `AdaptRequest` and the reviewer's `ReviewRequest` carry it as `plot_language`. The adapter writes the title, axis titles, legend entries and annotations in it, while column names and labels from the data keep their spelling; a change whose base version was written in another language carries `language_changed`, and its literal budget of 300 characters grows by 1.5 times the literal text the plan replaces, up to the first adaptation's 2,000, so a translation fits but a long new annotation on top of it does not. The reviewer judges the plot's own text against it under VQ-06, fail-open: a title or an annotation plainly in another language fails, a name or a label from the data never does, and a text whose language it cannot judge is no defect. Code, comments, the `changes` notes and the root's `change_request` stay English. After every run, `done` carries `language: {language, source}`, so the page syncs its chip after a turn in which detection or `set_language` changed it. The fixed refusals keep their hand-written lines, in every chip language and Polish, with the English fallback: a judged refusal uses the message's language, and a refusal sent before the judge (`budget`, `unsupported_content`) uses the session language's code (`language.refusal_lang`: a code as it is, a known name such as `Deutsch` through a small table, anything else English). Versions made before a change keep their text, each version stores the language it was written in, and the feedback bundle carries `session.plot_language` and `plot_language_source`. Fonts for non-Latin scripts are the renderer's concern (a separate change).

### Request flow for "Find the right plot type" (phase 2)

The compact `id|title|cat:tags` index (about 13.7k tokens, cache-eligible) is appended to the root's `static_instruction` in phase 2 only; step 1 is page-scoped and the index would cost those tokens on every root call. The root calls `find_specs` (AND across categories, OR within one, values checked against the tag vocabulary) and `get_spec_knowledge` (including the synced "What a good version looks like" bullets) for at most three candidates, derives filters from the pasted profile, and replies with `[[spec:id]]` tokens that the UI turns into cards. `select_spec` validates the choice and swaps the snapshot. Embeddings (pgvector 0.8.5 on Cloud SQL PostgreSQL 18 plus gemini-embedding on `eu`) are added only if evals show that the index is insufficient.

## Contracts

Schemas live in `agents/anyplot/schemas.py`: `ColumnProfile{name≤64, dtype, missing, unique, min, max, mean, median, top≤5}` (`mean` and `median` for integer and number columns, six significant digits; the model-facing JSON leaves every empty field out), `DatasetProfile{rows, columns≤50, sample≤5 rows with cells≤40 chars fenced as <user_data>, source_format, decimal, warnings}`, `Binding{role ^[A-Za-z_][A-Za-z0-9_]{0,31}$, column}` (digits and capitals because 21 of 325 specs name roles such as `log2_fold_change`, `lower_95` or `temperature_K`), `PipelineArgs{change_request≤600, base: catalogue|previous, theme: light|dark = light}`, `AdaptRequest{code (working form), profile, bindings, loader_columns, hints, change_request, feedback, previous_plan?, allow_full, plot_language, language_changed}`, `Edit{find (exactly one match), replace}`, `AdaptPlan{edits≤20, full_code≤24 KB (repair attempts only), title≤120, changes≤5}`, `ReviewRequest{render_id, code, bindings, profile_summary, spec_brief, change_request, gate_notes, plot_language}`, `Defect{id ∈ fixed set, theme light|dark|both|code, observed, target, likely_cause}`, `Verdict{ok, defects≤5}`, `PlotResult{status ok|needs_attention|failed|not_ready, reason?, attempts, artifacts, changes, residual_defects}`, where `artifacts` lists the PNG of the rendered theme only.

### Parse

`agents/anyplot/data/parse.py` has no ADK import. Limits: UTF-8 at most 200 KB, 50 columns, 20,000 rows and 200 characters per cell. It rejects NUL and control characters, strips the BOM, applies NFC, and strips zero-width and bidi control characters. Headers are canonicalised (NFC, control characters stripped, names over 64 characters renamed, duplicates suffixed, empty names become `column_N`, each rename a warning), and the canonical names are written into `data.csv`, which is the single source of column names. Formats: JSON records, a column map, an object of values or an array of `[category, value]` pairs (the last two become the columns `category`, the keys kept as text, and `value`, source format `json_pairs`; nesting depth at most 2; a repeated key keeps its last value, with a warning), or delimited text with the delimiter sniffed from `, ; \t |`. A Python literal (`[`, `{` or `(`, also behind an assignment such as `cat_day = {...}`, which is stripped) is read like JSON with `ast.literal_eval`, which evaluates literals only; a name or a call is refused, and a bracket count that skips quoted strings and comments refuses more than 50 nesting levels before anything is evaluated. Text that starts with a bare `(` and is neither JSON nor a literal (a header such as `(in %) Land`, prose in parentheses) is delimited text as before. Everything is read as text first, then dates with explicit formats (an ambiguous day/month order is a warning), then numbers; a decimal comma is accepted only with a date guard. A column whose every cell carries the same unit (`65 %`, `15,6 h`, `€ 5`, `CHF 1.200`, also with a no-break space between number and unit) is read as numbers, the unit moving into the column name (`Anteil (%)`) through the canonical-header path, with a warning, unless the header already names the unit; a column where only some cells carry a unit, or two units, stays text, as does one whose "unit" is a month, a boolean or an ordinal suffix (`5 Jan`, `1st`). The output is a canonical `data.csv` (comma, dot decimal, ISO dates) in a session-scoped dataset store (in memory, tied to the session's lifetime, the idle sweeper and the DELETE route; never a `user:` artifact, which would outlive the session and be listable by the model), plus the profile and default bindings (role dtype match, then name similarity, each column once; roles without typed bullets stay empty and the UI asks; a role that needs values of 0 or more never takes a column with a negative value, see `agents/anyplot/data/signs.py`: role names that are magnitudes in every spec, such as `radius`, `size`, `count`, `std`, `weight`, and `value` only in part-of-whole, area and flow plots such as pie, donut, treemap, sunburst, icicle, waffle, marimekko, sankey, rose and the basic funnel, never in signed ones such as waterfall or diverging bars; a binding of one by hand stays valid and becomes a warning in the session block, the `set_bindings` result, the PUT route's `warnings` and at the page's dropdown, through the role's `non_negative` flag). `bindings.apply(session, bindings, source)` validates roles against the snapshot's data roles and columns against the profile; the PUT route (through `session_service.append_event` with a `state_delta`) and the `set_bindings` tool both call it, and both answer `409` while a run is active.

### Adapt and validate

`agents/anyplot/code/` has no ADK import. Every version has two forms: the **working form** contains the literal placeholder `df = load_user_data()` and is what the adapter edits; the **run form** has the loader substituted and the normaliser applied and is what runs and what the user downloads. Order of operations: apply the edits to the working form, validate with the ADAPTED profile (the placeholder is allowed), normalise, substitute the loader, then render and export the run form. `base="previous"` and every repair attempt always get the latest validated working form; if the previous attempt failed validation, the next one gets the original plus the previous attempt's edits as `previous_plan`.

- **Normaliser** (per runtime; matplotlib and seaborn first): drop `bbox_inches`, keep the figure size and rescale the dpi so the output hits 3200x1800 or 2400x2400 exactly (within the canvas gate's 16 px when the aspect is a hair off and no dpi is exact), strip the `sys.path` guard, the catalogue header and the catalogue title (the title string becomes `""`; the call that shows it stays). The canvas is never an LLM repair target.
- **Readiness scan** on the normalised original: `blocked` (the 13 map specs, a library that is not enabled, a SECURITY validator failure, no `THEME` block, a non-literal savefig target), `coupled` (literal limits, data-coordinate annotations, literal statistics, short palettes, hard-coded date locators; these findings go to the adapter as hints), or `clean`.
- **Edits** apply in order. Each `find` must match exactly once and may not overlap a protected region. Matching goes from strict to tolerant and is never fuzzy: an exact substring first, then the same with the blanks before line breaks ignored, then whole lines whose words agree once indentation and runs of blanks outside string literals are ignored, with the replacement moved by the one indentation shift between them. A string literal's text must agree exactly, and a line inside a multi-line literal never matches this way. The first tier that finds anything decides, so more than one match there is a failure. A `find` that matches, in any tier, only the code before an earlier edit of the same plan changed it is reported as such (`stale_match`). Protected regions are found by AST: the `THEME` assignment, every theme token (a module-level assignment that tests `THEME == ...` and is built only from literals, `THEME` and earlier tokens: `PAGE_BG`, `ELEVATED_BG`, `INK*`, `GRID`, `BRAND`), the placeholder line, and the final savefig statement. A theme conditional that reads the data, such as box-basic's `_tight_text_color = INK if THEME == "dark" else IMPRINT_PALETTE[tightest_idx]`, is plot code the adapter may change. After a plan, a protected statement must keep its meaning, compared as a syntax tree, so a full file that re-states a token in other quotes or spacing passes. The `IMPRINT` palette list is not protected: it stays one literal list, assigned once, that keeps its existing entries in order and may only be extended with further positions from `core/palette.py`, which the validator checks. With more than eight groups the adapter keeps palette colors for the seven largest and draws the rest in the theme's muted ink as one "Other" group, which the reviewer accepts under VQ-07.
- **Loader**: exactly one `df = load_user_data()` in the working form. The server replaces it with `pd.read_csv("data.csv", dtype=..., parse_dates=[...])` using a relative path, so the exported code also works in notebooks.
- **Validator profiles.** The SECURITY rules run on the normalised original (eligibility) and on every adapted working form: `ast.parse` on at most 48 KB; imports only from COMMON (numpy, pandas, math, statistics, datetime, collections, itertools, functools, textwrap, colorsys, re, and since the owner's decision of 2026-10-10 the pure computing modules warnings, typing, calendar, decimal, fractions, zoneinfo, enum, dataclasses, operator, bisect, heapq, numbers and cmath; not `string`, `locale` or `random`) or the per-library allowlist (the plotting submodules, for matplotlib and seaborn also the bundled `mpl_toolkits.{mplot3d,axes_grid1,axisartist}`, `scipy.{stats,interpolate,signal,cluster.hierarchy,spatial,optimize,special,integrate,ndimage,fft,linalg,constants}`, sklearn without `datasets`, `statsmodels.{api,nonparametric,tsa,graphics}`; third-party helpers such as cartopy or adjustText stay out); never `statsmodels.formula`, `scipy.io`, `scipy.datasets`, sys, pathlib, importlib, subprocess, socket, urllib, requests, shutil, ctypes, pickle or io; `os` only as `getenv("ANYPLOT_THEME", ...)`; a `banned-import` message names the module and what to use instead, and the finding carries a label of the path for the attribution log (its longest prefix in a closed vocabulary of module names, else `?`); each admitted module was walked for names that read, write, fetch or evaluate, and those are banned (`warnings.formatwarning`, `showwarning` and `warn_explicit`, `zoneinfo.reset_tzpath`, `available_timezones` and `ZoneInfo.from_file`, `typing.get_type_hints` and `ForwardRef`, `operator.attrgetter` and `methodcaller`, `enum.global_enum`, calendar's `LocaleTextCalendar`, `LocaleHTMLCalendar` and `different_locale`, which set the process locale, and `calendar.main`, which reaches them and is banned on the calendar module only, because a column may be called `main`); module re-exports that reach what the import rules keep out are banned as attributes on any object and as `from` imports (`sys`, `os`, `builtins`, enum's `bltns`, `modules`, `inspect`, `subprocess`, `importlib`, `pathlib`, `shutil`, `socket`, `linecache`, `CodeType`, `FunctionType`), and so is any private name (one leading underscore) of an imported module, such as `collections._sys` or `dataclasses._FuncBuilder`; both rules cover the components of an import path below its root as well, so `import scipy.fft._backend as backend` is refused; a module bound by `import` is only ever the receiver of an attribute, never a value, so `[calendar][0]` is refused; and the dangerous private helpers a walk of the allowed modules found (`_sys`, `_locale`, `_random`, `_tzpath`, `_common`, `_getcategory`, `_FuncBuilder` and numpy's `_datasource`) are banned by name on any object, so a module reached through an attribute chain or a `from` import cannot hand them out either; banned names `eval`, `exec`, `compile`, `open`, `__import__`, `input`, `breakpoint`, `globals`, `locals`, `vars`, `getattr`, `setattr`, `delattr`, `memoryview`, `exit`, `quit` and the three-argument `type()`; every name, attribute or keyword matching `^__\w+__$` and any string literal containing a dunder identifier; banned attributes `.format`, `.format_map`, pandas `.eval` and `.query`, `memmap`, `ctypeslib`, `f2py`, `matplotlib.use`, `show`; banned calls: pandas `read_*`, `ExcelFile`, `HDFStore` and the I/O writers (`to_csv`, `to_pickle`, `to_parquet`, `to_excel`, `to_sql`, `to_hdf`, `to_feather`, `to_json`, `to_html`, `to_clipboard`, but not `to_datetime` or `to_numpy`), `np.load*`, `save*`, `savetxt`, `fromfile`, `fromregex`, `DataSource`, `loadtxt`, `genfromtxt`, `ndarray.tofile`, `plt.imread`, `matplotlib.image.imread`, `matplotlib.cbook.get_sample_data`, `mpl.rc_file`, `load_dataset`, `fetch_*`, `urlopen`; no class, async, await, yield, global or nonlocal statements, no star or relative imports; no `http(s)://`, `ftp://`, `file:` or `data:` literals; string literals at most 200 characters and at most 2,000 characters of new literal text per plan; the savefig target is exactly `f"plot-{THEME}.png"`; `def` and `lambda` stay allowed for formatters. The ADAPTATION rules run on adapted code only: exactly one placeholder; no RNG used to create data (a seeded `np.random.default_rng(<int literal>)` is allowed for jitter and subsampling, and the row-fidelity gate catches fabricated data); numeric literal lists of at most 20 items; the palette prefix preserved. SECURITY failures reject the code and get a repair attempt while one is allowed; ADAPTATION failures become defect lines. Every bypass named here is a validator-corpus test.

### Render

`agents/anyplot/render/` defines `RenderJob{job_id, language, library, source, data_csv, themes, timeout_s}` and two protocols: `RuntimeAdapter` (`file_name`, `command` as the CI command verbatim, `env`, `loader_block`, `normalise`, `validate`, `collect`) and `RenderBackend` with the backends `remote` (phase 1: the `anyplot-renderer` service, `AGENT_RENDERER=remote` with `AGENT_RENDER_URL`), `sandbox` (sandboxes launched inside the agents service; a stub that phase 1 does not use), `local` (development only; refuses `ENVIRONMENT=production`; always `docker run --rm --network none --read-only --tmpfs /tmp -v <rundir>:/work <renderer image> /app/.venv/bin/python -I /opt/anyplot/harness.py plot.py` with the production renderer image, fails if Docker is missing, no bare-subprocess fallback) and `fake` (unit tests, fixture PNGs).

The renderer is a service of its own (owner decision of 2026-10-10), so the deployed agents service and a developer's `adk web` render in the same sandboxes. `agents/renderer/` has no ADK import and no `__init__.py` (`adk web agents` would list it as an agent). `POST /render` takes the `RenderJob` as JSON and answers per theme the exit code, a timeout flag, a stderr tail of at most 2,000 characters, the probe, the PNG as base64 (at most 10 MB), the attempts and a reason (`timeout`, `disk_budget`, `file_budget`, `memory`, `launcher` or `output_rejected`) with the measured value and the limit, plus the slot wait, the total time and `MemAvailable`; `POST /render/{job_id}/cancel` stops that job's render; `GET /status` reports the version, the slot, stuck launchers, `MemAvailable`, whether the launcher exists and whether the run volume is in place. `agents/renderer/wire.py` is the JSON contract that both the service and the `remote` backend read. The renderer only runs code and returns its outputs; the host gates and the probe gates below stay in the agents service, and R1 turns a reason into a line that names the limit and the measured value, so the repair knows what to change. Every route needs an IAM-forwarded ID token whose `aud` is in `RENDERER_AUDIENCES` (the service URL, which the deploy adds, plus the OAuth client ids of the owner's user tokens) and whose `email` is in `RENDERER_ALLOWED_CALLERS`; the check is the one of `/v1`, reads `X-Serverless-Authorization` whenever it is present, and is skipped only in development. An unexpected error answers `500 {"detail": "internal"}` and is logged by its class only, so the `remote` backend never mistakes it for a front-end error and runs the job again.

The sandbox command per theme, started with `asyncio.create_subprocess_exec` in a session of its own and never a shell, with a fresh name and a fresh run directory for every launch:

```
/usr/local/gcp/bin/sandbox do --sandbox-name r-<random>-<theme> \
  --mount type=bind,source=/tmp/runs/r-<random>-<theme>/work,destination=/work -w /work \
  --env PATH=/app/.venv/bin:/usr/local/bin:/usr/bin:/bin --env HOME=/tmp --env ANYPLOT_THEME=<theme> \
  --env MPLBACKEND=Agg --env MPLCONFIGDIR=/tmp/mpl --env ANYPLOT_MPL_SEED=/opt/mplconfig \
  --env ANYPLOT_RLIMIT_CPU_S=60 --env ANYPLOT_RLIMIT_FSIZE_MB=50 --env ANYPLOT_RLIMIT_AS_MB=1024 --env ANYPLOT_RLIMIT_NPROC=64 ... \
  -- /app/.venv/bin/python -I /opt/anyplot/harness.py plot.py
```

What spikes S and S2 measured in europe-west4, and what the executor (`agents/renderer/executor.py`) does about it:

| Fact | Consequence |
|---|---|
| The sandbox is gVisor with no egress, no metadata server and only `lo`; `--write` makes its root filesystem writable, and with it a nested egress attempt got one step further | No `--write` and no `--allow-egress`, asserted in code; renders work without `--write` |
| A sandbox's environment holds only `HOME`, `LC_CTYPE` and the `--env` values, with no `PATH` | `PATH` is passed explicitly, with the rest of a complete environment |
| The code runs as uid 0; the image and every host file outside `/tmp` are readable from inside, sibling run directories are not, and each sandbox gets a private `/tmp` tmpfs of about 1.9 GiB | Every run directory and every user byte lives under `/tmp/runs/<run>`; the image holds no secret; the harness copies the baked font cache from `/opt/mplconfig` to `/tmp/mpl`; the fallback fonts under `/usr/share/fonts/noto` are read from the image |
| A disk fill through `/work` on the plain filesystem crashed the whole instance at about 3.4 GB | `/tmp/runs` is a 512 MiB in-memory volume, which the service checks at startup on Cloud Run (`503 volume_missing` without it), and a host watchdog measures each live run directory every 50 ms and kills the sandbox above 64 MiB (`disk_budget`) or 10,000 entries (`file_budget`); a tree deeper than 32 levels or past `PATH_MAX`, which a walk by path cannot measure, counts as over its limit |
| Each sandbox's private `/tmp` counts as instance memory, and no flag bounds it | The same watchdog reads `MemAvailable` and kills the sandbox below 512 MiB (`memory`); the remedy for the budget itself is an open decision |
| `RLIMIT_CPU`, `RLIMIT_FSIZE`, `RLIMIT_AS` and `RLIMIT_NPROC` are enforced inside; the defaults bound nothing | The harness sets 60 s, 50 MiB, 1 GiB and 64, soft and hard alike; the host keeps its wall-clock timeout |
| `sandbox delete --force` exits 0 even when it did nothing | On a timeout, the watchdog, a cancellation or an unexpected error: `os.killpg` with SIGKILL, then `sandbox delete --force <name>`; the kill counts only when the launcher process exits, and one that does not exit within 10 s is `stuck`, which refuses further renders with `503 stuck` and, on Cloud Run, ends the service's process so a fresh instance replaces it. A launcher that exits non-zero on its own also gets a `delete` |
| One of 26 renders ended in 0.4 s with `failed to exec in container ... exit status 137` and no output | A non-zero exit without the harness's `HARNESS {"event": "start"}` line is retried once with a new sandbox name; a second one is reported as `launcher`; a failure after the harness started goes to the repair |
| The cgroup's `memory.current` is unreadable | `MemAvailable` from `/proc/meminfo` is logged with every render and refuses a render below 1,024 MiB (`503 low_memory`) |
| Many concurrent sandboxes crash a 4 GiB instance; one is safe | One render slot per renderer, themes one after the other, a 30 s wait for the slot (`503 busy`) |
| `/healthz` never reaches the container | No health route; Cloud Run's TCP startup probe |
| matplotlib renders in about 2.5 s and seaborn in about 3.3 s at p95, at 2 vCPU | `AGENT_RENDER_TIMEOUT_S` (60) is far above a normal render |

stdout and stderr are read while the sandbox runs and kept bounded (the first and last 4 KiB of stdout, the last 64 KiB of stderr, of which 2,000 characters go back), and the outputs are read with `O_NOFOLLOW` and `fstat`, so a symlink, a FIFO or an oversized file is refused (`output_rejected`). The probe is written by the code under test, so the renderer drops one nested deeper than 16 levels or holding a number a float cannot carry, and turns `NaN` into null; the harness's own peak-memory and CPU line is taken only as finite numbers in range. An `OSError` on the host (a full volume, a failed fork) is `503 io`, never a plot failure. The log carries ids, exit codes, reasons and timings, never code, data, stderr or images; `/var/log/sandbox.log` on the host records every launcher call and is the source of truth for launcher metrics.

uvicorn does not cancel a request handler whose client went away, so `POST /render` runs the render as a task, races it against the connection's `http.disconnect`, and cancels it when the caller is gone; the executor's kill path then stops the sandbox and frees the slot. Because Cloud Run's front end may not pass a closed connection on, the `remote` backend also posts `/render/{job_id}/cancel` when its own render is cancelled (an abort, the request deadline) or its answer does not come in time. `job_id` and the requested themes are an idempotency key (the backend sends one request per theme under the job's id): the backend's retry after a connection error or a front-end 429 or 5xx may replay a request that did reach the renderer, so a replay with the same payload joins the render in flight or gets the stored answer of a finished one (the last 16), and another payload under the same key is refused with `409 job_conflict`; a job's code never runs twice because of a retry, and the last caller to leave is the one whose departure cancels the render.

The `remote` backend mints the ID token for `AGENT_RENDER_URL`, the renderer's service URL, from the metadata server on Cloud Run; in development it sends `AGENT_RENDER_TOKEN` when set, or the `id_token` of the developer's Application Default Credentials (`agents/README.md`). It retries a connection error or a Cloud Run front-end 429 or 5xx without the renderer's JSON `detail` after 1, 3, 8 and 15 s within 30 s (spike S saw a 500, then a 429, and a 200 about 17 s after the first request to a service scaled to zero), never the renderer's own refusals. A `launcher` reason becomes `RendererUnavailable`, because it is the renderer's failure and not the code's, so it spends no repair and the theme toggle records no try; every other failure maps to `RendererUnavailable` too, and its message is logged.

A run renders one theme, the one `PipelineArgs.theme` names, and the host gates judge exactly the themes of the job (an output for another theme is ignored, a missing one fails R1). The theme toggle renders the other theme of a finished version later, as a job of its own with the same code and `data.csv`, and adds its PNG to the version's render. Renders are strictly serial per instance, because spikes S and S2 showed one 4 GiB instance serves one sandbox at a time safely. No backend keeps a semaphore of its own: `Services.backend` wraps whichever backend `make_backend` built in `SerialRenderer` (`render/serial.py`), which renders one theme per slot under `AGENT_RENDER_CONCURRENCY` slots, 1 by default, so every backend is serial by construction, `adk web` runs included; the `remote` backend therefore sends one theme per request. The renderer holds one render slot of its own on top, because the deployed agents service and a developer's `adk web` call it independently. A freed slot goes to a waiting pipeline render before a waiting theme toggle, so a run waits for at most the render in progress; a render's timeout starts when it runs. The theme toggle records a theme that failed the host gates and renders it at most twice; a renderer that could not run is not recorded. `harness.py` (copied into the renderer image at `/opt/anyplot/harness.py`) prints its `HARNESS` start line, sets the resource limits soft and hard alike (CPU seconds and file size always; the address space and the process count when the renderer passes them, because outside a sandbox `RLIMIT_NPROC` counts every process of the user), copies the baked font cache into `MPLCONFIGDIR`, appends the installed fallback families (`FALLBACK_FAMILIES` in `harness.py`: Noto Sans, Noto Sans CJK JP, and the Noto Sans faces for Arabic, Hebrew, the nine Indic scripts, Thai, Khmer, Myanmar, Ethiopic and two symbol blocks) to every font lookup after the font the code chose, so DejaVu Sans stays the catalogue's first font and text in any of those scripts still draws, whatever `font.family` the code or seaborn's `set_theme` set; records every code point matplotlib reports as having no glyph in any font of its text, plain text and `$…$` math alike, as `missing_glyphs` in the probe; registers a `Figure.savefig` probe that writes `probe-<theme>.json`, calls `runpy.run_path`, and prints its peak memory and CPU time in a closing `HARNESS` line.

Host gates: R1 (exit code and outputs present) and R2 (PNG hardening: `lstat` with no symlinks, at most 10 MB, magic bytes, Pillow under `MAX_IMAGE_PIXELS`, non-blank with less than 98 % background, re-encode) are blocking; a render that fails either is discarded and never becomes `best`. R3 (canvas within 16 px through `core/canvas.py`, lifted from `.github/workflows/impl-review.yml`) is repair-triggering with a fallback: an R3 miss after normalisation is a defect line for the repair; if it persists after the last allowed attempt, the host pads the PNG of the rendered theme to the target canvas (never crops), the padded artifact counts as having passed the host gates, and the result ships as `needs_attention` with the residual line `canvas padded after render (<theme>)` and the VQ-05 line for that theme, never silently. A job with both themes pads each theme that missed and keeps the other theme's PNG as it rendered. The theme toggle answers a padded theme as `needs_attention` with the reason `canvas_padded`. The probe gates (G3 clipping, G5 annotation out of view, G7 overlapping text: tick labels among themselves, and since 2026-10-12 every other drawn text (axis label, title, legend text, annotation, or a text no role names) against any drawn text by more than 3 px, named by role and never by content, with a polar hint when an axis label of polar axes is involved, after the owner's polar case where the radial label `y` sat on the `270°` tick label and the reviewer called it missing; G8 row fidelity, G9 more than 200,000 plotted points, G10 characters without a glyph) are advisory because in-sandbox data can be tampered with: they can only trigger a repair or add notes, never fail a render. Since 2026-10-12 the probe also describes each polar axes (`polar`: the radial labels' angle, the visible theta span and a histogram of the plotted points by 5° of angle and by tenth of the radius range, all in the axes' own theta coordinates), and `agents/anyplot/render/polar.py` turns it into a measured target, not a gate: when the radial tick labels' ray holds plotted points and a ray every 22.5° inside the span holds at most half as many, `GateReport.repair_hints` gets one line such as "polar radial tick labels: at 67.5° they sit on 10 plotted points → ax.set_rlabel_position(270), the freest direction, 0 points there. Likely cause: ...". It never starts a repair; a repair attempt that runs for other findings carries the latest render's line first among its `hints`, and the adapter prompt says to apply it with exactly that value. The owner's case of that day (seaborn `polar-scatter`, `y = sin(x)`) had the repair guess 67.5°, onto the data; evenly spread angles give no line, but a cardioid does, because a point counts only when its distance from the ray as a share of the radius is small and it is outside the innermost tenth. The first attempt gets no such hint: nothing is rendered yet, and the angle of the user's column as the plot will draw it (degrees or radians, offset, direction) is only known from the render. A renderer limit that stopped a run (`memory`, `disk_budget`, `file_budget`, `output_rejected`) is recorded as `R1-<reason>` among the failed gates. The defect-line helpers (`DEFECT_RE`, `weakness_class`, `defect_ids`, and the `format_defect` builder) live in `core/defects.py`, the canonical stdlib-only implementation, and the PNG auto-reject checks (AR-04 blank and AR-07 format; R2 calls `check_blank` with its 98 % threshold) live next to the canvas gate in `core/canvas.py`, so the agents image needs no `automation/` or `scripts/` files. `automation/scripts/regen_gate.py` keeps a parity-tested copy of the grammar, because the workflows run it as a single-file copy with the runner's system Python, where `core` is not importable. The pipeline switches to `core.defects` in the later change that also switches the canvas gate and updates the copy sites: the `cp` step in `impl-review.yml`, the `git show` in `impl-generate.yml`, `review_retest.py materialize`, and the overlay in `review-retest.yml`.

**Scripts and fonts.** Plot text can be in the scripts most users' data and languages bring: the renderer image installs Noto Sans, Noto Sans CJK and the Noto Sans faces of the scripts DejaVu Sans lacks (37 files, 46.8 MB, Regular and Bold where the family has both), and the harness appends them to every font lookup, so a Chinese title or a Devanagari tick label draws with the right glyphs while the code's own first font stays in charge of Latin text. Right-to-left scripts work: the pinned matplotlib lays text out through libraqm, so Arabic and Hebrew render shaped and in reading order, within one label aligned by the code's `ha`. Three limits remain, and G10 reports the first and the last: a `$…$` math string uses matplotlib's math fonts without fallback and draws `¤` for every character they lack, so non-Latin words belong outside math text; Han characters take the Japanese regional forms of the CJK face until a caller passes the plot's language (`text.language`, a follow-up with the language chip); and a character outside the installed families draws as a Last Resort placeholder box. Most pictographs are not in that last group, because Noto Sans Symbols2 or DejaVu Sans draws them as monochrome outlines (📈, 📊, ⚠, 😀), but 🔥, ✅, the flag letters, Tibetan and Mongolian have no glyph in any installed font. G10 counts those characters deterministically from matplotlib's own reports, names up to three of them with their code points (`U+1F525 🔥 fire`), tells the repair that a user's column name stays as it is, and keeps the line in the result's residual lines even when the reviewer passed the render, because a measured missing glyph is not a judgement.

Later languages reuse the CI commands: `Rscript plot.R`; `julia --project=/opt/julia plot.jl` with a stacked `JULIA_DEPOT_PATH` and a pinned `JULIA_CPU_TARGET`; `node /opt/anyplot/js-render/render.mjs plot.js` with `window.ANYPLOT_DATA` injected; bokeh with `BOKEH_RESOURCES=inline`, `SE_OFFLINE=true` and a shipped chromedriver; plotly with local or disabled MathJax.

### Footer strip

Every PNG a user sees or downloads carries a strip appended below the plot (owner decision of 2026-10-10): "made with any.plot()" on the left and "anyplot.ai/<spec-id>" on the right. `agents/anyplot/render/watermark.py` composites it at image level after the run, so it never enters the user's code, and everything upstream keeps the raw render: the host gates R1 to R3, the probe gates, the reviewer, the render store's `pngs` and the exported `plot.py`. Only the artifact route's `plot-light.png` and `plot-dark.png` and the feedback bundle's images carry it. The route composes the strip in a worker thread on the first request and caches it in the render store next to the raw PNG (`StoredRender.shown`, counted against the same 256 MiB cap; a cached strip gives way to a new render before the store reports itself full). `AGENT_WATERMARK=false` serves the raw renders, and the eval harness sets it so its renders stay comparable with its baselines.

The geometry is defined on the 3200 px canvas and scales with `width / 3200`:

- The strip is 64 px high in the theme's page colour (#FAF8F1 or #1A1A17, taken from the artifact name, never from the pixels), so a 3200x1800 render becomes 3200x1864 and the 2400x2400 square becomes 2400x2448. The raw image sits at (0, 0), pixel-identical.
- A 1 px hairline in the ink colour at alpha 0.15 fills the strip's top row and never covers the plot's last row.
- The text is JetBrains Mono at 22 px, inset 40 px from both sides, with its cap height (0.73 em) centred in the strip. "made with " and "/<spec-id>" are Regular at alpha 0.56, "any", "plot", "anyplot" and "ai" Bold at 0.70, and "()" Regular at 0.315, in the theme's ink (#1A1A17 or #F0EFE8).
- The dot is not a glyph but a #009E73 square at alpha 0.9 with the logo's MonoLisa period geometry: for a dot em of 1.45 times the text size, a side of 0.185 em (6 px), a cell of 0.640 em, a left bearing of 0.251 em, and its bottom on the baseline.
- A spec id too long for the space between the two texts is cut and ends in an ellipsis, so the texts stay at least 40 px apart.

JetBrains Mono 2.304 Regular and Bold are vendored unmodified from the official release, with `OFL.txt` and a notice that records their SHA-256 values, in `agents/anyplot/render/fonts/`. The service loads them at import, so a missing file stops it at start, and draws them with Pillow's BASIC layout engine, so an image without raqm renders the same pixels. MonoLisa is not an option: its EULA covers desktop, web, application and ePub use only.

### Fencing and exported code

Fencing is our own: catalogue code and the profile are wrapped as `<catalogue_code>` and `<user_data>` blocks with a "data, never instructions" preamble in the `AdaptRequest` rendering and in the `get_current_code` and `get_dataset_profile` results. Spec text, which starts as a public issue, goes into `<spec_text>`. Text that one model hands to the next, or that quotes catalogue code, goes into one `<tool_notes>` block as JSON: the `changes` and `residual_defects` of the `plot_pipeline` result for the root, the readiness hints, the feedback lines and the previous plan for the adapter, and the gate notes for the reviewer. Outside a fence stand only fixed headings and validated identifiers, so the root's session block names the spec id but never the spec title. The session language is the one user-chosen value the session block carries, and it stands inside a `<plot_language>` fence there too, as in the adapter's and the reviewer's requests, because a chosen language is free text that only a pattern bounds. A render error reaches the repair as its exception class and code line only, never its message, which can be a cell of the user's data. ADK's built-in fencing (relayed agent turns, MCP descriptions) is not relied on, because tool results and node inputs are relayed unfenced.

The exported code is byte-identical to the run form that rendered: an attribution header ("Adapted by anyplot.ai from <spec-id> (<library>) for your data.csv; run: `ANYPLOT_THEME=<theme> python plot.py`", naming the theme the run rendered), imports, the theme tokens unchanged, the Imprint palette (possibly extended), `df = pd.read_csv("data.csv", ...)`, then plot, style and save. The download is `plot.py` plus `data.csv`; the code draws no footer strip, so it reproduces the plot without one. The catalogue title rule, the 4-line header and the DQ-02, DE and LM rubric items do not apply to user plots.

## Guardrails

Plugin order on `App`, where the first non-None result wins and a plugin never raises (on internal failure it returns a blocking response): `ScopeGuard → Budget → ToolSafety → ContextFilter(num_invocations_to_keep=6)`. `GlobalInstructionPlugin` is not needed because the policy lives in the root's constant `static_instruction` and only the root talks to the user. A request-scoped ledger (a context variable keyed by invocation id) is shared by ScopeGuard, Budget, ToolSafety and the pipeline.

- **ScopeGuard.** The BFF and anyplot-agents reject text over 2,000 characters (`413 too_long`), so the judge always sees the whole message. In `on_user_message` it skips structured actions, blocks non-text parts, checks the per-user and global budget in the ledger before calling the judge and books the judge's `usage_metadata` to it, and judges all text parts plus the last assistant turn (at most 500 characters; after a refusal, the fixed refusal the halt stored) and the user's last three earlier turns (at most 1,500 characters), with delimiters escaped (spaced and fullwidth tag forms too), so a request split across three turns is judged as a whole; the root sees six invocations, so a request spread wider than the judge's window is bounded by the plot-text budget below instead. The verdicts are `in_scope`, `out_of_scope`, `attack` and `needs_data` (a request for data the service would have to fetch, such as stock prices, the weather, statistics, a URL or a public dataset). The rubric counts a message that also asks for anything out of scope, text meant for use outside the plot (emails, posts, newsletters, summaries, translations) and plot text whose purpose is an advertisement, a call to action or a message to other people as out of scope, judged by intent: a name, a postal address, an e-mail address, a phone number or a web address in the data, the plot or the message is never on its own a reason to refuse, because users plot their own tax returns, contact lists and customer tables; a message whose only part beyond the plot is data to fetch, a plain fact question included, is `needs_data`. A timeout, parse error or non-200 after one retry within 4 s blocks with a distinct `error{code:"guard_unavailable"}` that is excluded from the false-refusal metric; the retry waits 0.5 s first (`JUDGE_RETRY_BACKOFF_S`), because a 429 or a transport error retried in the same instant meets the same cause, and on a per-minute quota every failed call counts too. Any other verdict than `in_scope` replaces the message with `[message withheld by scope policy]` before it is stored, and `before_run` halts with the fixed refusal from `refusals.yaml` in the language the judge names (hand-written English, German, French, Spanish, Italian, Portuguese, Dutch, Polish, Chinese, Vietnamese and Russian texts in the informal address; the Chinese, Vietnamese and Russian texts and the revised Portuguese and Polish ones, added on 2026-10-12 without a native speaker at hand, passed a back-translation review and a separate naturalness review; English for every other language; no model writes or translates a refusal): `needs_data` with the `needs_data` text (no internet source can be tapped; paste the data as a table), the others with the `out_of_scope` text. The judge's `lang` for the session's first in-scope typed message becomes the session language with the source `detected`, unless the user has chosen one; a refusal sent before the judge (`budget`, `unsupported_content`) uses the session language instead (see [Session language](#session-language)). Each `attack` verdict of the scope or dataset judge is a strike, counted once per distinct message or dataset, so retrying one input that the judge wrongly called an attack costs one strike; from `AGENT_ATTACK_STRIKES` (3) strikes a day on, the user gets the budget refusal for the rest of the UTC day, and only a new day, a redeploy or a scale-to-zero resets it. Every token-path caller of the BFF shares one user id, so in phase 1 the owner's own jailbreak testing on that path spends the shared strikes: raise `AGENT_ATTACK_STRIKES` for such a session, or use a separate user id. With `AGENT_KEEP_REFUSALS` (off by default) a refused message's text and verdict stay in a ring of 20 per session in memory, shown only in the feedback bundle; this is a phase-1 stub, readable while the session lives through the bundle the page's `.save()` downloads (`GET /debug/agent/sessions/{sid}/bundle` on the BFF, since 2026-10-12), until the refusals are stored with the quick feedback. The dataset judge call at parse time uses the same plumbing with a data rubric that judges injection only, never personal data, behind a deterministic pre-filter for text addressed to an AI. In `on_event` the ScopeGuard also checks the root's final reply before ADK stores it, with the output guard's reply cap below, and stores a refused reply as the fixed refusal, so it never re-enters the judge's or the root's context; after a `plot_pipeline` call it stores the reply cut at the cap instead.
- **Budget.** `before_model` halts with a fixed `LlmResponse` only for the root, because a halt inside the adapter or the reviewer would break their schema parsing; the pipeline calls `budget.check()` before each `run_node` and finishes with `PlotResult(failed, reason=budget)`. `before_tool` on `plot_pipeline` counts pipeline runs. Limits: per request 12 calls or 160k tokens; per user per day 40 pipeline runs or 2M tokens (about 54 warm runs, so the run cap binds first, but about 26 for a user whose every request starts cold); global per day 6M tokens, three users at their daily budget, which pauses the service. The token limits count cost-weighted tokens: each kind weighs its list price relative to an uncached input token (cache read 0.1, cache write 1.25, output 5; `BUDGET_WEIGHTS` in `plugins/ledger.py`), and the judges' tokens count as well. With a warm prompt cache the median run of the spike-X rerun booked about 37k weighted against 70k plain tokens. On a cold cache a reviewed run with two attempts books about 78k, and the costliest one about 115k with a second review (117k with three attempts), which the 160k request limit holds with about 36 % to spare. Before a review the pipeline also keeps 35k (`REVIEW_RESERVE_TOKENS`) for the review and the root's closing reply, so a tight budget skips a review rather than answering a shipped plot with the `budget` refusal; the reserve is the measured need, and the guarantee is structural: once a plot has shipped in the invocation, the root's next call is exempt from the halt once and runs without tools, so it can only be the closing reply (bounded by the root's 4,096-token output cap); any further root call is checked again. Phase-1 daily counters live in memory for one instance lifetime, and the `aiplatform` spend cap is the real backstop; persisting the counters is a phase-2 item. The plugin writes one attribution JSON line per hook (request id, HMAC user, session hash, agent, tool, argument hash, verdicts, usage, `model_version`, latency) and never content.
- **ToolSafety.** `before_tool` enforces a per-agent allowlist (the root's seven session tools and its `plot_pipeline` workflow; none for the adapters and the reviewer), Pydantic validation of the arguments (`FUNCTION_TOOL_ARG_VALIDATION` is off by default), no links (`http`, `https`, `ftp`, `file`, `data` or `javascript` with text right after the colon, or `www.`; a caption such as "Data: my tax return" is not one) or paths in string arguments, as link hygiene, and at most one `plot_pipeline` call per invocation. Personal data in a `change_request` (a name, an address, an e-mail address, a phone number, a bare web address such as `jana-novak.de`, which the root writes without its scheme and `www.`) passes: whether plot text is an advertisement or a message to other people is the scope judge's call, by intent. In the pipeline, a change of a previous version may add at most 300 characters of new string literals (bytes literals and f-string parts included; 2,000 for the first adaptation and for a change that switches the session language, and 2,000 for all versions together against the catalogue code; dataset headers and cells are free): the budget bounds how much text the model writes, not what it says. `after_tool` applies a key allowlist and an 8 KB cap (24 KB for code). `on_tool_error` returns `{"status":"error","code":ENUM}` and never exception text.
- **Output sanitiser** in the stream translator, deterministic: `message` events only for `author == "anyplot"` final responses (adapter, reviewer and pipeline-branch events map only to `status` and `plot`); strip URLs with a scheme or `www.`, `data:`, `javascript:` and `mailto:` links, HTML, markdown images and fenced code blocks longer than 10 lines; keep `[[spec:id]]` only for registry ids; cap text at 1,200 characters; final text only. Personal data stays: names, postal and e-mail addresses, phone numbers and bare web addresses pass through to the chat, and only a link with a scheme, `www.` or `mailto:` is stripped, as link hygiene. The output guard (`agents/anyplot/output_guard.py`, run by the ScopeGuard before the reply is stored) replaces a root reply longer than 1,200 characters once sanitised with the fixed `out_of_scope` refusal, the same in every language, with no word list. A turn that called `plot_pipeline` is the exception: its reply describes a plot the user already has, so it is stored and sent cut at 1,200 characters (attribution verdict `reply_cut`) instead of a scope refusal after the plot, which would read as a false refusal. The root's "two to five sentences, or a short list" is about 300 to 900 characters across languages, and a list of eight steps fits in about 600, so the cap leaves a third on top. It counts characters, not sentences, because a sentence count needs a segmenter per script and counts every list item. The cap bounds how much one reply can carry; a short off-topic reply that got past the judge is not caught by it.

## Feedback capture

Every agent result can be reported with one click and a short text, and the report carries the full case, so prompts, validator rules, gates and the model pin can be tuned from real sessions. It mirrors the site feedback (`api/routers/feedback.py`, `FeedbackWidget`, triage under `/debug/feedback/*`) but stores a case bundle instead of a message.

Built since 2026-10-12, the capture half. Every result card carries the control (`app/src/sections/agent-chat/ResultFeedback.tsx`): the four reactions, an optional text of at most 500 characters, `# include data.csv` (ticked by default), and `.send()`, which shows `sent · v<n>` afterwards and takes an edit that stores a new case; sending never waits for a turn and never starts one. The BFF route `POST /debug/agent/sessions/{sid}/feedback` (`api/routers/agent.py`, `api/agent_cases.py`) fetches the version's bundle from anyplot-agents and writes the case to `cases/<case_id>/` in the bucket that `AGENT_CASES_BUCKET` names (`anyplot-agent-cases` by default): the PNG of each rendered theme, `plot.py`, `data.csv` only with the box ticked, and `manifest.json` last, with every field of the planned table row below plus `case_uri` and the bundle without its PNGs and data ([Feedback case](../reference/api.md#feedback-case)). The case id is the UTC time plus eight random hex digits, so ids sort by time; no upload replaces an object. An edit sends the earlier case's id as an optional `replaces`, which the manifest keeps, so the triage can tell which case an edit replaces; without it, the newest case of a session hash and version is the one that counts. The replaced case stays in the bucket, its `data.csv` too, until the lifecycle rule deletes it. The bundle carries no `model_version`, token or cost totals yet, so those manifest fields are `null`. `agents/evals/import_case.py` turns a saved bundle (`.save()`) or a case directory copied from the bucket into an eval case in the git-ignored `agents/evals/.cases/`, which the harness reads as promoted cases (`agents/README.md`, "Import a feedback case"); its expected outcome follows the triage rule below, thumbs up `accepted`, thumbs down `rejected`, and `--expected` for bug and idea. The bundle stores no change request and no bindings per version, so the tool matches a version's request by position only when the transcript's plot turns and the versions agree in number, and refuses otherwise until you pass the request yourself. The triage half is built since 2026-10-12 as well: the `agent_feedback` table and its migration, the "Agent cases" section in `DebugPage`, and `agents/evals/sync_cases.py`, which pulls the promoted cases from the bucket. Not built yet: the delete-my-case route.

- **UI.** On the result card and in the chat page's floating-action slot: thumbs up, thumbs down, bug and idea (the existing reaction set), an optional text of at most 500 characters, and a checkbox "include my data file" (on by default for admins in phase 1; off by default and behind an explicit consent notice for real users later). Sending is optional and never blocks the flow. One submission per result version; a later edit replaces it.
- **Route.** `POST /debug/agent/sessions/{sid}/feedback {reaction, message?, include_data, result_version}` on the BFF, behind `require_admin` in phase 1; the public phase reuses the feedback router's per-IP-hash rate limit and honeypot. The BFF calls `GET /v1/sessions/{sid}/bundle` on anyplot-agents, which assembles the case on the server so that anyplot-agents stays credential-free: the transcript of user and root messages (never tool outputs or thoughts), the catalogue snapshot id, the working and run code of every version, the adapt plans and defect lines, the plot results, the dataset profile and bindings, the PNG of every rendered theme as the user saw it (with the footer strip) with its gate outcome, and a config stamp (`AGENT_PROVIDER`, `AGENT_MODEL`, `model_version` from `usage_metadata`, the judge model, prompt file hashes, validator and normaliser version, ADK version, token and cost totals, latency per step). `data.csv` is included only when `include_data` is set. Besides the feedback route, the chat page's `.save()` in the header downloads that bundle through the BFF's `GET /debug/agent/sessions/{sid}/bundle` as one JSON file (`anyplot-session-<id>.json`, with `data.csv` while its `# include data.csv` box is ticked, the phase-1 default), so a session can be kept and handed on by hand.
- **Storage**, written by the API, which already has database and GCS access: a row in a new table `agent_feedback` (Alembic migration) with `id, created_at, user_hash, session_hash, spec_id, library_id, language, reaction, message, include_data, status (new|in_progress|done|wont_solve), case_uri, model, model_version, prompt_hash, pipeline_status, attempts, tokens, cost_estimate`; the bundle as `cases/<id>/{manifest.json, plot-light.png, plot-dark.png, plot.py[, data.csv]}` in a new private EU bucket `anyplot-agent-cases` (public-access prevention, uniform access, lifecycle delete after 180 days by default; never `anyplot-images`). The attribution log stays content-free; the case bundle is the only place content is stored, and only on explicit submission.
- **Triage.** A new "Agent cases" section in `DebugPage` lists cases with filters by reaction, status, spec, library and model version, opens a case (transcript, code diff against the catalogue original, the image of every rendered theme, defect lines, config stamp), updates the status, and offers **Promote to eval case**, which asks for an explicit expected outcome (`accepted` or `rejected`; the form preselects `accepted` for thumbs up and `rejected` for thumbs down, and makes the owner choose for bug and idea reactions, because those do not map to a fixture outcome) and copies the case (dataset, bindings, spec and library, the chosen outcome) to the `evals/cases/<id>/` prefix of the same private bucket. The harness syncs that prefix into a gitignored `agents/evals/.cases/` directory at run time. Promoted cases are never committed: they contain users' data, and anything under `agents/evals/fixtures/` ships under the repository's MIT licence. Only synthetic fixtures (the spike-X perturbation datasets) are committed. This is the bridge from real sessions to the regression harness.
- **Feedback without a plot.** Since 2026-10-12 a session that made no plot can be reported too: the owner's session that asked for a feature column from a sine table never reached a result card, so he had to paste its JSON by hand. Below the composer, while the thread has a turn and the session has no version, `# no plot yet? tell us what went wrong` opens the same control (`ChatFeedback.tsx`) as `# feedback on this chat`; it sends `result_version` 0, the chat itself. The bundle route answers `version=0` with the conversation, the profile, the bindings and no version, and with `include_data` the session's current data as the top-level `data_csv` (`null` before any data, which the BFF answers with `422 no_data`; the control then shows `# no data yet` and cannot tick the box). The case holds `data.csv` (when asked for) and `manifest.json`, no image and no `plot.py`; its row carries `result_version` 0 and no pipeline status, and the same `replaces` chain links an edit. The triage labels it `chat, no plot`, shows no renders, and refuses its promotion (`422 no_plot`): the plot harness has nothing to replay, and `import_case` refuses it, because such a case belongs in the prep or scope eval fixtures.
- **Analytics.** `agent_result_feedback{reaction, include_data, subject}` with enum properties only; `subject` is `result` or `chat`.
- **Privacy.** Phase 1 holds owner data only. Before real users can submit: consent text on the control, a legal-page entry for the case store (purpose, retention of 180 days, EU bucket), `include_data` off by default, and a delete-my-case route keyed by the case id shown to the user.

## Model-version regression harness

Testing a newer model version, the other provider's arm, a different judge model, or a prompt or validator change is one command locally or one workflow dispatch in CI, and the answer is a diff against the pinned baseline.

Built on 2026-10-10: the harness, the two fixture generators and the 146 fixture cases (the 123 of the full matrix and the 23 stress cases with their model-free `--static` stage), the reports, the diff, the review gallery, the blind two-run gallery with its scoring, the model-free catalogue eligibility sweep `agents/evals/eligibility.py` (`agents/README.md`, "Run the regression harness"), and the judge-only scope eval `agents/evals/scope.py` with its refusal recall and false-refusal rate (`agents/README.md`, "Run the scope eval"; its first run passed both gates). Not built yet: `--prompts <dir>`, the Gemini baseline, and the CI workflow.

- **Fixture cases**, each a directory with `case.json` (spec, library, bindings, expected `accepted`, `rejected` or `unknown`, tags, the perturbation and the source of the data, and optionally a session `language` that the harness chooses through the language route before the first turn; a promoted case carries its session's when that was detected or chosen), `data.csv`, and an optional `change_request.txt`. Two sources: the committed synthetic fixtures in `agents/evals/fixtures/cases/<id>/`, which are the spike-X matrix (10 specs times matplotlib and seaborn times 6 perturbation datasets, written by the seeded generator `agents/evals/make_fixtures.py`) plus three hand-written cases (one of them, since 2026-10-12, a German follow-up message that sets the session language) and the 23 stress cases of `agents/evals/make_stress.py` (tag `stress`, left out of `full`; see [Bounds](#bounds)), and the promoted feedback cases synced from the private bucket into the gitignored `agents/evals/.cases/` directory (never committed, because they hold users' data). The tag `smoke` marks the 12 cases of the smoke set. The scope set is the judge-only case file `agents/evals/scope.evalset.json` (see Evals below); the injection and code-escape sets stay as flow evals.
- **Harness** (`agents/evals/matrix.py`, the spike-X runner made permanent): runs every case through the real `/v1` flow in-process (httpx `ASGITransport` against `agents.main:app`, the same plugins and run queue, the models from the settings, and the render backend `--renderer` names: `remote` against a deployed renderer, `local` in Docker, or `fake` for a dry run of everything but the render) with candidate settings that are passed only to the harness: `--provider` (alone it selects that provider's default models; the settings refuse a model from the other provider), `--model`, `--judge-model`, `--location`, `--cases smoke|full|stress|<glob>`, `--static` (only the model-free static stage of `agents/evals/stress.py`: parse, eligibility, bindings, loader, prompt sizes and the stand-in renders), `--repeats N`, `--budget-usd` (stop before a case that could take the estimated list-price cost past it), and `--gcloud-token` (mint the developer's renderer token with the gcloud CLI and renew it before its one-hour expiry). Before the first case it renders each library's catalogue file once through the configured backend, without a model call, and stops with exit code 2 when that fails; during the run a pipeline that ended in `RendererUnavailable` (the `error` class on its `pipeline_result` attribution line), or three errors in a row, stop it with exit code 4, so an outage never becomes a matrix of failed runs or a baseline. Per case it records the status and reason, attempts, gate failures by gate, validator rejections, edit-apply failures, the reviewer verdict, LLM calls, `model_version`, tokens (prompt, candidates, thoughts, cached, cache writes, the judge's input and output), cost at list price, the time to the first event, the end-to-end time and the render time, and, since report schema 2, the stage that stopped each attempt and the run (for example `adapter_truncated`, `edit_apply` or `reviewer_defects`, never a bare `validation`), the shipped and the last reviewed attempt, each attempt's adapter outcome, finish reason and plan shape, the edit-failure kinds, every model call's finish reason and tokens, the answers that failed their schema, by agent kind and outcome (`answer_outcomes`: `repaired` or `refused`) and by broken rule (`answer_rules`), the edits each tolerant matching tier applied (`edit_tolerant`), and the module labels of banned imports (`banned_imports`). It reads them from the stream and from the content-free attribution lines that the pipeline, the Budget plugin and the judges write per request id. It writes `<out>/<date>-<model>.json`, a Markdown summary, and a review gallery of 30 renders sampled at random from the runs that passed, with an accept and reject pair each and a JSON export, and prints a diff table against `agents/evals/baselines/<pinned-model>.json` (or `--baseline`) over the cases both reports hold: pass rate, accept-match rate (cases whose outcome matches the case's expected outcome), cost per successful plot, p50 and p95 latency, and every case that flipped. A run passes when it ships a render that passed every deterministic gate (no padded canvas, no ADAPTATION finding); every rate counts harness errors as runs that did not pass. The owner's judgement is the acceptance measure: to compare two arms, `python -m agents.evals.report blind` merges both reports into one gallery of the same cases with the arm hidden in a separate key file, and `report score` gives the acceptance per arm. The exit code is 1 when the pass rate on the shared cases drops below the baseline minus a tolerance (5 percentage points by default) or a run crashed in the harness, 2 for a setup error, 3 when the budget stopped the run, and 4 for an outage.
- **Baselines.** `agents/evals/baselines/claude-haiku-5-5.json` is committed with the default model: the thinking run of 2026-10-11 on main at `e2e25ef61` (122 cases with one run each, root thinking 1,024 and adapter thinking 2,048, through the deployed renderer; 122 passed, 62 `ok`), which replaced the thinking-off rerun of spike X of 2026-10-10 (244 runs). `gemini-3.8-flash.json` follows with the Gemini arm, so the price and quality comparison is a diff between two reports. `--save-baseline` refuses a run that stopped early, holds promoted cases, or has a run that ended in an error. A model bump is a PR that changes the `AGENT_MODEL` default and adds the new baseline file; a unit test asserts that a baseline exists for the pinned model once any baseline is committed. The same mechanism covers judge-model bumps and ADK upgrades, because the ADK version is part of the report stamp.
- **CI.** `.github/workflows/agents-eval.yml` has `workflow_dispatch` inputs `provider`, `model`, `judge_model`, `location`, `cases` (smoke or full) and `repeats`, and a nightly `smoke` run on the pinned model. It authenticates through Workload Identity Federation, sets `GOOGLE_CLOUD_LOCATION=eu`, uploads the report as an artifact and writes the diff table into the job summary. It mirrors the candidate-versus-baseline pattern of `review-retest.yml` (see [Review retest](../workflows/review-retest.md)). A lifecycle probe in the nightly run calls `models.get` on the pinned model and fails loudly on a 404 or a retirement notice, so a forced bump of the pinned model, or of the Gemini arm's short-term 3.8 Flash tier, is noticed before users are.
- **Cost.** A full run is 123 cases times at most 2 attempts. Measured on 2026-10-10 at list price for the full matrix: $0.52 on the Claude Haiku 5.5 arm ($0.0051 per passed plot, median $0.0041, 4.77 model calls per run) and $15.89 on the Gemini 3.8 Flash arm ($0.169 per passed plot, median $0.124, 4.80 model calls per run, $3.99 of it on failed runs); `smoke` (12 cases) is about a tenth of a full run. Both fit inside the spend cap.

- **`anyplot-agents`**, a new Cloud Run service built from `agents/Dockerfile` and deployed by `agents/cloudbuild.yaml` (both built on 2026-10-10; the service has run at `https://anyplot-agents-r3tvmejsmq-ez.a.run.app` since 2026-10-11, deployed by the `deploy-agents` trigger on every push to `main` that touches it) with the renderer's candidate-then-smoke-then-promote steps and `--update-*` flags only. Like the renderer's, its deploy step creates the service on the first build without `--no-traffic`, because gcloud rejects `--no-traffic` on a new service, and only when `services describe` reports the service as not found; the API side stayed dark through `AGENT_ENABLED=false` until the switch-on of 2026-10-11. Flags: `gcloud run deploy anyplot-agents --region=europe-west4 --execution-environment=gen2 --no-allow-unauthenticated --service-account=anyplot-agents@anyplot.iam.gserviceaccount.com --cpu=2 --memory=4Gi --min-instances=${_MIN_INSTANCES} --max-instances=1 --concurrency=20 --timeout=900 --update-env-vars=^|^... --no-traffic --tag=candidate`, where `_MIN_INSTANCES` is 0 unless a build sets 1. No secrets and no Cloud SQL in phase 1. The smoke step checks that Cloud Run IAM refuses an anonymous `GET /v1/status` with exactly `403` (a `401` would come from the container's own caller check, past IAM) and, with `_SMOKE_AUTH=true`, calls `/v1/status` with an ID token impersonated for `anyplot-agents@` (the renderer's token recipe) and checks that it names the provider, model, location and libraries the build configured; the bootstrap build runs with `_SMOKE_AUTH=false`, because the service has no URL and no invoker binding before it exists. The image installs `--extra agents` without plotting extras, copies the source tree with the prompts, the fonts and the catalogue prompt sources at their repository paths, runs as uid 1000, and fails its build when a prompt source or a font is missing: the build imports `agents.main` and reads the two judge rubrics, which the service otherwise reads on first use. The root `.dockerignore` keeps `agents/evals` and ADK's local `.adk/` store, both of which can hold users' data, out of the image. `.github/workflows/ci-image.yml` builds it before merge and checks `/v1/status`, the production default's `401` for an anonymous caller, the files in the image and the uid. The concurrency and the timeout follow the run queue, not the memory: the queue, not Cloud Run, limits the runs in memory, but every queued run holds an open stream, so the instance must accept the queue's 10 waiting streams, the run in flight and the other routes (`--concurrency=20`), and one turn can last the 600 s maximum wait plus the 180 s deadline (`--timeout=900`). The FastAPI app in `agents/main.py` sets `docs_url=None`. The service runs no code of its own users: it has no `--sandbox-launcher`, and every render goes to `anyplot-renderer` through the `remote` backend. Its 2 vCPU and 4 GiB were sized when it still hosted the sandboxes; a smaller instance is an open decision.
- **`anyplot-renderer`**, a phase-1 Cloud Run service that runs the code (`agents/renderer/`), deployed by `agents/renderer/cloudbuild.yaml` with the same candidate, smoke and promote steps. Its deploy step creates the service on the first build, because gcloud refuses `--no-traffic` for a service that does not exist yet; it does so only when `services describe` reports the service as not found, and stops on any other describe error, so a permission or API error never sends all traffic to an unsmoked revision. Flags: `gcloud beta run deploy anyplot-renderer --region=europe-west4 --execution-environment=gen2 --sandbox-launcher --no-allow-unauthenticated --service-account=anyplot-renderer@anyplot.iam.gserviceaccount.com --cpu=2 --memory=4Gi --min-instances=${_MIN_INSTANCES} --max-instances=1 --concurrency=4 --timeout=300 --add-volume=name=runs,type=in-memory,size-limit=512Mi --add-volume-mount=volume=runs,mount-path=/tmp/runs --no-traffic --tag=candidate --update-env-vars=^|^ENVIRONMENT=production|RENDERER_ALLOWED_CALLERS=...|RENDERER_AUDIENCES=...`, where `_MIN_INSTANCES` is 0 unless a build sets 1 to keep an instance warm. One instance with one render slot, because renders are serial; `--concurrency=4` so a second caller gets the slot's `503 busy` after 30 s instead of a Cloud Run 429, and a cancel reaches the instance while a render holds the slot; the run directories on the in-memory volume (see [Render](#render)). No public domain, no secrets, no Cloud SQL and no role: the service account exists only to be an identity. The process runs as root, because `sandbox do` creates the gVisor sandboxes; the model-written code runs inside them. The smoke step checks that IAM refuses an anonymous caller (403) and, with `_SMOKE_RENDER=true`, checks that `/status` reports the launcher and the volume and renders a matplotlib plot through the candidate as the service's own account, which proves the launcher, the volume and the harness together. The build impersonates `anyplot-renderer@` for that token (`gcloud auth print-identity-token --impersonate-service-account`), because a build cannot mint an ID token for its own identity: gcloud refuses `--include-email` for it and Cloud Build's metadata server has no `identity` endpoint (builds `da6f53f5` and `a9d3ac7f` of 2026-10-10). The token is minted for the service URL while the requests go to the `candidate` tag URL, because Cloud Run accepts no other audience. `.github/workflows/ci-image.yml` builds the same image before merge and renders a seaborn plot through its harness.

- **SSE protocol `anyplot/1`**, translated from ADK events and never forwarded raw: `ready{v, run_id}`, sent before the run waits in the queue; `status{step:"queued", position, waiting}` while it waits, at once, on every change and every 15 s unchanged (`position` 1 runs next, `waiting` counts every queued entry, this one included); `status{step, attempt}` for the pipeline's steps; `message{text}` (root final text only), `plot{PlotResult}`, `refusal{code, text}`, `error{code, ref}` with codes `capacity` (also for a run that waited the queue's maximum), `deadline`, `guard_unavailable`, `upstream` and `internal`, and `done{llm_calls, tokens, bindings?, data_confirmed?, dataset?, language?}` (the last four are optional: after a run `bindings` and `data_confirmed` carry the session's bindings and whether the data is confirmed, so the page syncs its dropdowns and its step after a turn in which the root's `set_bindings` changed them, `dataset` carries the new data version after a turn in which the root's `prepare_data` or `generate_data` changed the data, and `language` carries the session language as `{language, source}`, `source` one of `default`, `detected` and `chosen`, so the page syncs its chip; a turn refused before the queue, such as the budget refusal, and a session gone meanwhile omit them). The translator tolerates the ADK 2.x `node_info` and `output` fields. A user already over the daily budget gets `ready`, `refusal{code:"budget"}` and `done` without waiting in the queue. Because queued time does not count toward the agents service's deadline, the BFF restarts its own turn budget (`AGENT_REQUEST_TIMEOUT_S`) on every queued status, with the queue's 15 s heartbeat on top because the run may start that long before its first event, and on the first event after the wait. Nothing moves a turn past `AGENT_TURN_MAX_S` (890 s), which stays below anyplot-api's `--timeout=900`: a turn still queued when its run could no longer finish inside that cap ends with `error{code:"capacity"}`, and closing the upstream stream takes it out of the queue before it spends a token.
- **Frontend.** A lazy `app/src/pages/AgentChatPage.tsx` at `debug/agent`, laid out as one chat column (since 2026-10-11, "chat first"). ## Verification

- **Regression harness.** `uv run --extra agents python -m agents.evals.matrix --model claude-haiku-5-5 --cases smoke --renderer remote --render-url <renderer URL>` must reproduce the committed baseline within tolerance on every PR that touches `agents/anyplot/prompts/`, `code/` or `render/` (run through `workflow_dispatch`, not automatically, because it spends money). - **Evals.** The scope set is judge-only (`uv run --extra agents python -m agents.evals.scope`, built and first run on 2026-10-10): it sends the 188 synthetic cases of `agents/evals/scope.evalset.json` to the judge the settings name, with the same context the ScopeGuard builds from each case's earlier turns (after a refusal, the fixed refusal as the last assistant turn, as the halt event stores it), without ADK, the root or a render, for about $0.05 a run. It paces the judge calls at 25 a minute by default (`--calls-per-minute`), so a run takes about 7 minutes: the project's Vertex AI quota for Claude Haiku in `eu` is 30 requests per minute, failed calls included, and unpaced runs hit HTTP 429 after about 60 cases; a case the judge could not answer keeps the cause, the failure's exception type. The cases are 70 in scope (four of them with personal data: payee names, an address column, an e-mail address in a byline, and a payment reminder on the user's own tax plot, which must not read as a call to action; since 2026-10-11 six requests to draw a formula or a curve, three English and three German, tagged `formula`, which the assistant computes and never fetches; since 2026-10-12 six requests to write the plot's own text in another language, three English and three German, tagged `plot_language`, which are in scope, unlike a translation for use outside the plot), 53 off-topic and 65 adversarial (German, role play, base64 and other encodings, multi-turn drift, general-programming requests framed as plot-code questions, mixed and plot-framed requests, advertisements and calls to action in plot text, and requests for data the service would have to fetch, a plain fact question included); each has `text`, `last_turns`, `expected` (`in_scope`, `out_of_scope`, `attack` or `needs_data`), `lang` and `tags`. It reports adversarial recall, the false-refusal rate, refusal recall, the exact and `needs_data` exact rates, a confusion matrix and a per-tag table, and exits non-zero below 100 % adversarial recall or above 5 % false refusals; a `--tags` subset gates only the metrics its cases measure and writes its own report file. The first run (2026-10-10, Claude Haiku 5.5 in `eu`, $0.054, on the 176 cases the set held then) passed both gates: 100 % adversarial recall, no false refusal and 98.8 % exact verdicts. Two attacks framed as plot-code questions got `out_of_scope` instead of `attack`, the same refusal without a strike, and two base64 cases and a cipher case got no verdict because the judge's answer failed its schema twice, which the service turns into a blocking `guard_unavailable`. This eval measures the judge only; the output guard's reply cap has its own case set in the unit tests (a long customer mail, a long Japanese essay and a list of sixty items that must be refused; change lists, how-to-run steps and five-sentence replies in English, German, French, Spanish, Italian, Portuguese, Polish, Japanese and Chinese that must pass). Not built: a second stage that sends the adversarial cases the judge passes through the real root and checks that the reply equals the fixed refusal. The flow evals (`use_with_my_data`, `injection` through CSV cells, headers, image labels and catalogue-style comments, and `code_escape`) run as a pytest harness against the real `/v1` routes in-process with fixture CSVs, because the pipeline reads the snapshot, dataset and bindings from server-set state; trajectory, `token_usage_v1` and `inference_call_count_v1` are tracked as regressions. A full eval run costs about $1 to $3.

## Open decisions

Defaults apply until the owner decides otherwise.

- DQ-02 topics (politics, religion, violence) in user data: allowed as data, labels only.
- The Highcharts commercial licence for user plots (phase 2).
- An attribution header in exported code: yes.
- A footer strip on the served PNGs: decided on 2026-10-10, yes, at image level only (variant `s1c-jb-sq2`: JetBrains Mono, the dot as a brand-green square); the exported code stays without it, and `AGENT_WATERMARK=false` switches it off. See [Footer strip](#footer-strip).
- Disabling the Vertex 24 h in-memory cache (needs `roles/aiplatform.admin` and applies to all regions): no in phase 1.
- Retention periods for the legal page (phase 2).
- Scale-to-zero "session expired" versus `min-instances=1`: accept in phase 1.
- A named fallback model on `eu` for capacity failover, which deviates from one pinned model everywhere: none.
- The request timeout for a queued turn: a run at the back of a full queue needs up to 780 s (600 s in the queue, 180 s to run). Decided on 2026-10-10: anyplot-api runs with `--timeout=900` and the BFF caps a turn at `AGENT_TURN_MAX_S` (890 s), so the full wait is reachable through the BFF.
- The queue length: the owner's formula (rate x maximum wait / 60) assumes runs within the 60 s rate window, so with longer runs the back of a full queue waits the full maximum and gets `capacity`. Decided on 2026-10-10: the formula stays; admitting by an estimated start time (position times the larger of 60 s per start and the recent run time, divided by the concurrency) is the fallback if the live service shows many expiries.
- One run or toggle in flight per user, across sessions (stricter than refusing a toggle only while that session runs): decided on 2026-10-10, kept.
- Whether the "Create plot" action carries the site theme, so a dark-mode visitor's first render is already dark instead of a light render plus a toggle: not yet; the action renders light.
- Feedback-case retention and data inclusion: 180 days in the private bucket; `include_data` on by default for admins and off by default with explicit consent for real users.
- The sandbox's private `/tmp` and memory: spike S2 counts each sandbox's `/tmp` tmpfs (about 1.9 GiB, no flag to shrink it) as instance memory, which on paper puts even one sandbox (1 GiB address space, 1.9 GiB `/tmp`, the 512 MiB volume) above the 3 GiB budget of a 4 GiB instance. Measured on 2026-10-10 through the deployed renderer (a throwaway service, 2 vCPU, 4 GiB, one sandbox at a time): code that writes 40 MiB files into `/tmp` until it is full ends after 4.6 s with `OSError: [Errno 28] No space left on device`, the instance stays up with 3,328 MiB available afterwards (3,451 before), and the memory watchdog never has to fire. Decided: a 4 GiB instance with one sandbox at a time, without `RENDERER_BIND_TMP` (which stays available, untested) and without an 8 GiB instance; the validator (no file writes in user code), the serial slot, the `MemAvailable` floor before a render (1,024 MiB) and the watchdog's floor during one (512 MiB, reason `memory`) stay as the controls. Re-measure before a second render slot.
- How a developer's `adk web` authenticates to the deployed renderer: `AGENT_RENDER_TOKEN` from `gcloud auth print-identity-token` is the path spike S proved against Cloud Run IAM; the token minted from a user's Application Default Credentials carries the ADC OAuth client id as `aud`, and whether Cloud Run IAM accepts it is not yet verified. Either way, the token's client id joins `RENDERER_AUDIENCES` (both client ids are in the deployed service's `_AUDIENCES`) and the owner's email `RENDERER_ALLOWED_CALLERS`. Checked on 2026-10-11 against the deployed renderer: the gcloud CLI token renders (the harness and the local stack use it); the ADC token path is still unverified.
- Cold starts of the renderer: with `--min-instances=0`, the first render after an idle period meets a cold instance, and spike S saw the front end answer 500, then 429, and a 200 only about 17 s after the first request. The `remote` backend retries such answers after 1, 3, 8 and 15 s within 30 s. The deployed renderer runs with `--min-instances=0` since 2026-10-11, and the harness rendered through it that day without a retry failure, but no render has been timed against a deliberately cold instance yet; that measurement decides whether the retries suffice or the renderer runs with `_MIN_INSTANCES=1` (the billing commitments probably absorb its cost).
- Premium positioning: [Vision](vision.md) lists "Try with your data" as premium; the licensing row in the decisions table settles that the code stays MIT regardless.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Cloud Run sandboxes are in Preview with undocumented regions, isolation technology and cross-run visibility | Spikes S and G plus the probe suite gate phase 1; the `RenderBackend` protocol; the fallback is a gen2 service with Direct VPC egress deny or `GkeCodeExecutor` with a custom image; the sandboxes run in `anyplot-renderer`, a service of its own with a zero-role account, from phase 1 |
| The model adapts poorly (spike X: 83.6 % of the Claude arm's runs and 77.0 % of the Gemini arm's pass the gates, but only 14 of Claude's 122 runs end `ok`; unreadable reviewer answers, adapter schema misses and the palette rule are the first prompt and validator items, and the G3 clipping gate was a probe false positive, fixed in the probe; remote renders get the fix once the renderer image is rebuilt) | Spike X is the go or no-go with owner blind acceptance; an eligibility filter (statically clean data-generation pairs: matplotlib 65 of 251, seaborn 84 of 267; the dpi normaliser removes the canvas condition; plotly's 102 count only in phase 2); hints from the readiness scan; the normalisation workstream; an honest `needs_attention` status |
| Gemini 3.8 Flash, the second arm, is a short-term tier not on the tier list, and `eu` has its own capacity pool | One `AGENT_MODEL` value, `retry_options` with backoff from day one, `error{code:"capacity"}` on persistent 429s, no fallback model unless the owner names one, the lifecycle probe, an eval gate on every bump |
| The Vertex quota for Claude Haiku in `eu` is 30 requests per minute in the project `anyplot` (an override; Google's default is 1,500), failed calls included, and the service does not pace its judge calls: a wide dataset of 20 to 30 judge parts, four at a time, spends most of a minute's quota within seconds, after which the next upload or message fails closed with `guard_unavailable` until the minute passes | Open: raise the quota, or add a process-wide judge rate limit, which would make a wide upload wait up to a minute; failing closed keeps it safe meanwhile. The scope eval paces itself at 25 calls per minute (`--calls-per-minute`), and the judge's retry waits 0.5 s |
| The reviewer is a weak judge (expert correlation about 0.43) | Deterministic gates first, a short checklist, at most one repair by default (`AGENT_MAX_ATTEMPTS`), residual defects shown as notes, owner acceptance as the real metric |
| ADK ships weekly with feature-flag drift | An exact pin to 2.11.0; re-check `FUNCTION_TOOL_ARG_VALIDATION` and `JSON_SCHEMA_FOR_FUNC_DECL` on upgrade; plain-code modules without ADK imports; the harness report stamps the ADK version |
| Caller trust: anyplot-api runs as the shared compute service account | Acceptable while admin-only; the IAM-forwarded claims check; a dedicated service account before public use |
| Deadline overrun (2 renders of one theme times 60 s plus LLM calls) | A 140 s soft deadline inside the pipeline (skip the repair when less than 75 s are left, 60 s for its adapter call and 15 s for its render; clamp the render timeout); the Gemini adapter's 8,192-token edit cap, at which a cut-off first call takes about 58 s at spike X's fitted rate, so a cut-off still leaves the repair its 75 s (at 10,240 such a call would take about 72 s and cancel the repair; in exchange, a plan above 8,192 tokens loses its own repair round and comes back on attempt 2), a `try/finally` that always yields a `PlotResult`, the 180 s `abort_signal` backstop |
| Long SSE streams hold anyplot-api concurrency slots on its single instance | The 180 s deadline, the 890 s turn cap, one run per user, and a queue of at most 10 waiting streams; the route moves out of the API before public use |
| A queued turn outlasts a request timeout on its path: the 600 s maximum wait plus the 180 s deadline is 780 s | anyplot-api runs with `--timeout=900`; the BFF restarts its turn budget while the run waits but never past `AGENT_TURN_MAX_S` (890 s): a turn still queued when its run could no longer finish inside the cap ends with `error{code:"capacity"}` and leaves the queue before it spends a token, so Cloud Run never cuts a stream silently |
| Out of memory with more than one sandbox (spikes S and S2) | One run in flight; serial renders by construction, because `SerialRenderer` in `Services.backend` puts every backend and every route (the theme toggle and `adk web` included) behind the same slots, so a backend cannot forget its semaphore |
| Theme toggles crowd out paid runs (renders that cost no tokens but hold the one render slot) | A freed render slot goes to a waiting pipeline render first; one run or toggle in flight per user, and a toggle and a turn refuse each other in a session; a toggle waits for a slot at most 120 s; a theme that failed the host gates is rendered at most twice |
| Cloudflare 524 or Worker buffering | The generator route with automatic 15 s pings and first bytes sent immediately, verified in the phase-1 smoke test; asynchronous polling for slow runtimes later |
| A label in a script the image's fonts do not cover, or an emoji outside Noto Sans Symbols2 and DejaVu Sans (🔥, a flag), draws as placeholder boxes and the user reads the feature as broken | The harness records matplotlib's missing-glyph reports; G10 names the count and the characters to the repair and keeps the line in the residual lines after a reviewer `ok`; the CI image job renders seven scripts and a DejaVu-only control on every renderer change |
| Hidden CDN dependencies (bokeh, kaleido MathJax, map tiles) | The exclusion list of 13 map specs, inline and offline settings, the non-blank gate |
| Retiring defaults (`Gemini()` and the eval judge default to 2.5 Flash) | Always set `model`; the registry test asserts that every model string comes from settings |
| The spend cap trips on list price or on evals | A cap sized at list price with eval cost included; nightly smoke only; spike X in a throwaway project |
| The privacy page contradicts non-owner use | The owner-only gate; the legal PR and the retention design are hard gates |
