# A spec names the works it took ideas from, and no code is ever adopted from elsewhere

- Date: 2026-11-20
- Proposed: a colleague's project had given the idea for one plot of the catalogue, and nothing in a
  spec could say so. On a decision page the question was what a spec records about the works it
  builds on: which relations an entry can have, and whether code taken from another project could
  enter the catalogue with its own licence.
- Decided: two relations only, "inspired by" for a work that gave the idea and "references" for the
  literature whose values a spec follows. Code is never taken over from elsewhere, so no code header
  carries another project's licence, and the MIT License stays true for the whole catalogue. His
  answer on the decision page, with his reason: code never needs to be taken over, because nobody
  claims the data is correct; it only has to look correct and so be illustrative, and what is taken
  over are ideas.
- Where: `docs/reference/repository.md`, `core/spec_sources.py`
