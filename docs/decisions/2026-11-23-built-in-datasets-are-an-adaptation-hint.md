# A built-in example dataset in a catalogue file is a hint for the chat, not a refusal

- Date: 2026-11-23
- Proposed: The chat's validator refused every catalogue file that loads a built-in example dataset (a `sklearn.datasets` toy loader or generator, `sns.load_dataset`), which the generator prompts prefer and a regeneration keeps: 69 of 2,596 Python files loaded one, 68 of them were refused for that alone, and they are the machine-learning specs. The options were a validator rule that treats such a loader the way R's dataset packages are treated (a hint at eligibility, refused only in adapted code), generator prompts that replace the datasets with random draws, reworded specs, or no change.
- Decided: The validator rule: "Treat a built-in dataset in the original like R's dataset packages: a hint at eligibility, refused only in adapted code." The chat never runs the original; it runs the adapted code, whose data is the user's, so the eligibility scan reports the loader as a hint, adapted code that keeps the loader or its import is refused as before, and downloads (`fetch_*`) and loaders that read a path stay refused everywhere. A regeneration still keeps its data source (the rule of 2026-11-20), now for the consistency of the data scenario alone: the readiness gate no longer keeps a regeneration for adding such a dataset, because the chat refusal it guarded against is gone. That last point is the agents' reading, not his words.
- Where: `agents/anyplot/code/validate.py`
