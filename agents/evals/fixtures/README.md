# Eval fixture cases

Each directory under `cases/` is one case of the regression harness (`agents/evals/matrix.py`) and a development seed for `adk web` (`AGENT_DEV_FIXTURE=<case-id>`):

| File | Contents |
|---|---|
| `case.json` | `spec_id`, `library`, `locale` (the browser locale the session opens with; it never sets the session language), `bindings` (`[{"role", "column"}]`), `expected` (`accepted`, `rejected` or `unknown`), `tags`, and optionally `perturbation`, `source` (where the data comes from) and `language` (a session language such as `de` that the harness chooses through `PUT /v1/sessions/{sid}/language` before the first turn, source `chosen`; a promoted feedback case carries the language the imported version's text was written in, and none when the session's language was still the default) |
| `data.csv` | The dataset, synthetic; sent to the `/dataset` route exactly as a user would paste it |
| `snapshot.json` | Optional: the catalogue snapshot (`spec_id`, `title`, `description`, `data_roles`, `notes`, `code`, `library_version`). Without it the snapshot is built from `plots/<spec_id>/` in this checkout |
| `change_request.txt` | Optional: a follow-up message the harness sends after the plot is created |
| `standin.txt` | Stress cases only, optional: the middle of a hand-written working form, a stand-in for the adapter's answer that the static stage renders without a model |

A stress case's `case.json` also carries `bound_expected` (the gate, limit or error that must bound it), `needs_model`, `static` and `render` (what the static stage must measure), and for an injection case `marker`; `agents/evals/make_stress.py` documents each field.

There are 510 cases:

- **720 generated cases** `<spec>-<library>-<perturbation>`: 10 specs times matplotlib, seaborn, plotnine, altair, pygal, lets-plot (`letsplot`), ggplot2, Makie (`makie`), Chart.js (`chartjs`), D3 (`d3`), ECharts (`echarts`) and Highcharts (`highcharts`) times 6 perturbations (`renamed`, `x10`, `n12`, `n5000`, `date`, `decimal-comma`), written by `agents/evals/make_fixtures.py`. plotnine and altair joined on 2026-10-25, pygal and lets-plot on 2026-10-26, ggplot2, the first R library, on 2026-10-29 and Makie, the Julia library, and the four JavaScript libraries on 2026-10-30, each with the same datasets and bindings as the first two libraries. All ten ggplot2 files of the matrix specs are eligible: four are `clean` and six `coupled`, the files without the convention's `# Data` marker, which the adapter rewrites with the readiness hints (across the whole catalogue, 310 of 325 ggplot2 files are eligible and 15 blocked). All ten Makie files are `coupled`, since no catalogue Makie file carries column constants (308 of 325 eligible, 17 blocked). All forty Chart.js, D3, ECharts and Highcharts files are `coupled` too; across the catalogue 306 of 321 Chart.js, 311 of 325 D3, 311 of 325 ECharts and 310 of 323 Highcharts files are eligible, none `clean`, the rest blocked for the map specs and a few SECURITY findings (`qrcode-basic` in all four, `line-parametric` in Chart.js). The readiness scan blocks one of the ten pygal files (`line-timeseries`, two until `histogram-basic`'s regeneration of 2026-10-28), so its 6 cases are blocked when the session opens until that catalogue file changes. Never edit the generated cases by hand: change the generator and rerun `uv run --extra agents python -m agents.evals.make_fixtures`. Its docstring lists the specs, why each was chosen, the readiness of each spec's file per library, why the pygal file is blocked, and what each perturbation does.
- **7 hand-written cases**: `scatter-basic-matplotlib` and `bar-grouped-seaborn`, which the runtime tests also use, and `scatter-basic-matplotlib-german-message` (since 2026-10-12): German column names and a German follow-up message, `Mach die Punkte etwas größer.`, with no word about the language. The first plot comes from `create_plot`, which the scope judge never reads, so it is English; the follow-up is the session's first typed message and sets the session language to `de` (`detected`), so the second version must carry German plot text while the column names keep their spelling. The case names no `language` on purpose: it tests detection, not a choice. Each run's record holds the last `done` event's `language`. Four more (since 2026-10-15, tags `density` or `number-format`) generalise the live tests of 2026-10-14/15 and choose their `language`: `bar-grouped-matplotlib-many-categories-de` (26 invented regions times two series, where the catalogue's per-bar labels, dots and shadows crowded 52 bars; gate G11), `bar-basic-seaborn-decimals-de` and its English control `bar-basic-seaborn-decimals-en` (bar values with two decimals, which seaborn's `bar_label` wrote as `5.30` in a German plot; gate G12), and `line-multi-matplotlib-millions-de` (two population series in the millions with the follow-up `Zeig die y-Achse in Millionen, zum Beispiel 6,5 Mio.`, after an axis that read `6.0 M`; gate G12).
- **23 stress cases** `stress-<name>`, written by `agents/evals/make_stress.py` (rerun `uv run --extra agents python -m agents.evals.make_stress`): data at and one past the parser's caps, many categories, degenerate data, prompt injection, and requests that make the code compute mass data. They carry the tag `stress`; `--cases stress` selects them and `--cases full` leaves them out, so a full run keeps its 727 cases.

The tag `smoke` marks the 22 cases of `--cases smoke`: one generated case per spec, cycling through the perturbations and alternating matplotlib and seaborn; one generated case for each later library, `scatter-basic-<library>-renamed` for plotnine and altair (since 2026-10-25), for pygal and letsplot (since 2026-10-26), for ggplot2 (since 2026-10-29) and for makie, chartjs, d3, echarts and highcharts (since 2026-10-30); plus `scatter-basic-matplotlib` and `bar-grouped-seaborn`. The `renamed` headers have spaces and a dot, which test each library's own column syntax (ggplot2's `.data[[...]]`, Makie's `df[!, ...]` and JavaScript's `d[...]`, each with a column constant); pygal has none, so its case tests the axis titles that pygal never takes from a column name. A run that holds a case of any library but matplotlib and seaborn needs that library in `AGENT_LIBRARIES` (otherwise the readiness scan blocks the session as `library-disabled`) and a renderer image that carries it (otherwise the harness's preflight render stops the run).

146 cases open their session with `locale` `de`: the 140 generated `renamed` and `decimal-comma` cases, `bar-grouped-seaborn` (tag `german-locale`), the three German block H cases (which also choose `language` `de`) and the stress cases `cap-columns` and `mixed-decimals`. Since 2026-10-12 the locale sets no language, and their only turn is `create_plot`, so they reply and title their plots in English like every other case; their purpose is the data perturbation. `scatter-basic-matplotlib-german-message` is the case that exercises German replies and German plot text.

## Stress cases: what bounds them

Measured with the static stage on 2026-10-10 (WSL2, 32 cores; the stand-ins rendered through `harness.py` with the renderer's limits: 60 s CPU, 1 GiB address space, one BLAS thread). Parse times are the in-process `parse_dataset`; the renderer's 2 vCPU are slower. "Adapter request" is the rendered adapter input in characters, catalogue code included. CPU and peak memory are the harness's own end line; wall time is the harness process from start to exit. Launch the harness from a shell when you measure it again: `ru_maxrss` keeps a parent's peak across `exec`, so a harness that a Python process starts reports at least that process's memory.

| Case | Bound | Measured |
|---|---|---|
| `cap-rows` | accepted at 1,048,576 bytes and 20,000 rows (204,800 bytes before the paste cap rose on 2026-10-14) | parse 51 ms at 204,800 bytes; adapter request 3,402 characters |
| `cap-columns` | accepted at 50 columns, 200-character cells, Unicode and bidi | parse 32 ms; profile 12,138 characters, untrimmed (re-measured on 2026-10-11, when the profile gained `mean` and `median` for numeric columns and lost its null fields) |
| `cap-profile` | `MAX_ADAPTER_PROFILE_BYTES` (16,384 bytes of UTF-8) trims the adapter's profile | full profile 26,963 characters at the 1 MB cap, sent 6,281; adapter request 13,701 after the cap (re-measured on 2026-10-14) |
| `csv-expansion` | the renderer's 4 MiB `data_csv` limit (`MAX_CANONICAL_BYTES`; 2 MiB before 2026-10-14) | canonical `data.csv` 3,954,696 bytes, 3.8 times the 1 MB input |
| `over-bytes` | `413 too_long` before the parse | refused at 1,048,577 bytes, one byte over the cap |
| `over-rows`, `over-columns`, `over-cell` | `422 unparseable` (`too_many_rows`, `too_many_columns`, `cell_too_long`) | refused within 10 ms |
| `bar-100-categories` | G7 (advisory) | 99 overlapping tick-label pairs; 310 texts of the probe's 400; 1.8 s CPU (1.9 s wall), 131 MiB peak |
| `pie-30-slices` | the reviewer only | no gate fires: 92 texts, the legend covers the pie, small slices pile their labels; 1.0 s CPU (1.2 s wall), 127 MiB peak |
| `all-nan-column`, `mixed-decimals` | `422 invalid` at `PUT /bindings` | the column is typed text |
| `dates-centuries` | none needed | the parse types the column as a date (`date_columns` 1) and pandas 3 reads dates from 1066 to 2999 as datetime |
| `inject-header` | the `<user_data>` fence | judge, root, adapter and reviewer see it, always fenced. At the `/dataset` route the injection pre-filter refuses this upload before the judge (`403 data_refused`); the static stage does not run the pre-filter |
| `inject-row4` | the `<user_data>` fence | the judge and the adapter see the same five sample rows, so both carry it, the adapter fenced. The route's pre-filter refuses this upload too |
| `inject-long-cell` | none in text; the reviewer sees it as pixels | no prompt carries it; only `data.csv` does. Whether the plot draws it needs a model run (`needs_model`) |
| `compute-lorenz` | G9 (advisory) | 1,000,000 line points; 2.0 s CPU (2.1 s wall), 479 MiB peak; still renders with the address space cut to 610 MiB, fails at 605 MiB. At dt = 0.0001 (10,000,000 points) it peaks at 889 MiB (5.8 s CPU) and fails from 1,015 MiB down, a few MiB under the 1 GiB limit, so the case uses dt = 0.001 |
| `compute-oversample` | G9 (advisory) | 610,000 line points; 2.8 s CPU (2.9 s wall), 234 MiB peak |
| `compute-distances` | R1: `_ArrayMemoryError` under `RLIMIT_AS` | fails after 0.4 s CPU (0.6 s wall) asking for 18.6 GiB |

The other degenerate cases (`single-row`, `constant-series`, `duplicate-headers`, `empty-strings`) parse, bind and load. For `single-row` and `constant-series` only a model run shows how the plot copes, so they are marked `needs_model`; `duplicate-headers` and `empty-strings` claim only what the static stage checks.

Fixture data is invented. Never commit a user's data here: everything under `fixtures/` ships under the repository's MIT licence. Promoted feedback cases live in the private case bucket and are synced into the git-ignored `agents/evals/.cases/`, which the image build also excludes; until the sync exists, `python -m agents.evals.import_case` writes one saved session or stored case at a time into that directory, never into `fixtures/`.
